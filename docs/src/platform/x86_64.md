# x86_64

This page describes the **Stage-2 QEMU integration test path** for x86_64.
Stage 3a will expand it into the full architecture port (UEFI boot, ACPI,
APIC, SMP, context switch, syscall entry).

## What is delivered today

`kernel/arch/x86_64` is a *partial* Stage-3a baseline. It exists because
the two Stage-2 deliverable integration tests — `memory_isolation` and
`scheduler_stress` — need an x86_64 boot path. Specifically, the crate
provides:

- A **multiboot2** kernel header and a 32→64 long-mode trampoline
  (`boot.s`), chained from GRUB-EFI inside a `grub-mkrescue` ISO.
- Identity-mapped bootstrap paging covering the full 0–4 GiB physical
  window (`boot.s` + `paging`). Broadened from the original 0–32 MiB in
  Stage 3a (b) so the LAPIC MMIO frame at `0xFEE00000`, the IO-APIC frame
  at `0xFEC00000`, and any ACPI table OVMF/GRUB places in high memory
  below 4 GiB are reachable without further mapping.
- A minimal IDT for `#PF`, `#GP`, and `#DF` plus a closed-fail handler on
  every other vector (`idt`).
- A 16550 polled serial console on COM1 (`serial`).
- A QEMU `isa-debug-exit` helper (`qemu_exit`).

## Stage 3a (a) — platform discovery and APIC

Stage 3a (a) adds the *discovery* and *interrupt-controller* layer that
the remaining Stage 3a items (AP bring-up, context switch, syscall entry)
build on. Everything in this layer is `no_alloc` and host-unit-tested
behind MMIO / port-I/O traits so the same control flow runs under
`cargo test` as on real hardware.

| Module | Purpose |
|---|---|
| `multiboot2` | Zero-copy parser for the Multiboot2 information structure (tags 4, 6, 14, 15, 17). |
| `acpi` | RSDP v1/v2 checksum validation; generic SDT header; typed MADT entry iterator (Local APIC, IO-APIC, Interrupt Source Override, LAPIC NMI, Address Override). |
| `apic` | LAPIC + IO-APIC drivers. Software-enable, EOI, INIT/SIPI IPI sequence, IO-APIC redirection-entry programming. MMIO is accessed through the `LapicMmio` / `IoApicMmio` traits; the production impl uses `read_volatile`/`write_volatile` and a single `// SAFETY:` block per accessor. |
| `apic_timer` | PIT-channel-2-calibrated LAPIC timer. Pure ticks-per-second/initial-count math is split out into `compute_initial_count` and `compute_pit_reload` and unit-tested independently. |
| `bootmemory` | Bridge from Multiboot2 / UEFI memory-map entries to `MemoryRegionDescriptor`s. A dev-dependency on `kernel/mem` powers a round-trip test that fails the build if the local `RegionKind` mirror ever drifts from `rustos_kernel_mem::RegionKind` (AGENTS.md §2.2 — no duplication). |

What is **not** delivered yet, and is tracked in `PLAN.md`'s Stage 3a
sub-checklist: context switch / interrupt entry–exit prologue (Stage
3a (c)), `syscall`/`sysret` entry, and full `kernel/core::KernelArch`
wiring.

## Stage 3a (b) — AP bring-up

Stage 3a (b) adds the application-processor (AP) startup path so
RustOS actually drives ≥ 4 emulated cores on QEMU. It is fully
exercised end-to-end by `tests/integration/scheduler_stress_qemu`.

| Piece | Source |
|---|---|
| Position-independent real-mode → long-mode payload | `kernel/arch/x86_64/src/ap_trampoline.s` |
| Trampoline installer + `ApBootSlot` + INIT-SIPI-SIPI sequencer | `kernel/arch/x86_64/src/smp.rs` |
| BSP-side orchestrator (Multiboot2 → ACPI → MADT → per-AP bring-up) | `tests/integration/scheduler_stress_qemu/src/kernel.rs` |

Key invariants (audited per AGENTS.md §10; each `unsafe` block carries a
`// SAFETY:` justification):

- The payload is assembled into a dedicated `.ap_trampoline` section of
  the kernel image and copied to the fixed 4 KiB-aligned low frame at
  `AP_TRAMPOLINE_PHYS = 0x8000` at boot. The SIPI vector is therefore
  `0x08`, decoded by `smp::sipi_vector()`.
- The trampoline transitions directly from real mode to IA-32e long mode
  per Intel SDM Vol 3A §10.8.5 (PE+PG set together in one MOV to CR0).
  Internal jumps use absolute offsets bound to `0x8000` so the payload
  can be copied verbatim from any link address.
- The AP reads its `ApBootSlot` (`cr3`, `stack_top`, `entry`, `cpu_id`)
  from a fixed in-page offset (`0xF00`) and `xchg`-releases a `ready`
  flag the BSP `Acquire`-loads before launching the next AP. The 4 KiB
  trampoline frame is therefore serial-reusable.
- The BSP and APs all run on the same `boot_pml4` (identity-mapped
  0–4 GiB), so APs see the same memory map without any per-AP page-table
  work in (b).

No preemption is wired in Stage 3a (b); cores execute cooperatively in
`Scheduler::step(cpu_id)` and observe spawned tasks on their next loop
iteration. LAPIC-timer-driven preemption is Stage 3a (c).

## Stage 3a (c) — per-CPU GDT + TSS + IST (partial)

Stage 3a (c) is being landed incrementally. The first slice introduces
the **per-CPU descriptor-table primitives** every CPU needs to replace
the trampoline-internal GDT (`ap_trampoline.s`) and the boot-time GDT
(`boot.s`) with a real long-mode descriptor table.

| Piece | Source |
|---|---|
| `GdtEntry`, `tss_descriptor`, `Tss`, `PerCpuGdt`, `Selectors`, `GdtPointer` | `kernel/arch/x86_64/src/gdt.rs` |

What the new `gdt` module provides:

- A 7-slot canonical GDT layout — null, kernel code, kernel data, user
  data, user code, plus the two 8-byte slots of a 64-bit TSS descriptor
  (Intel SDM Vol 3A §8.2.3 Figure 8-4). The user CS sits *after* user
  DS so an eventual `IA32_STAR` programming resolves `sysret` SS/CS
  correctly (SDM Vol 2B §SYSRET).
- A `Tss` struct laid out per SDM Vol 3A §8.7 Figure 8-11, with
  `RSP0`..`RSP2` privilege stacks and `IST1`..`IST7` interrupt stacks.
  The `iopb` field is parked one byte past the TSS so userspace
  `in`/`out` always `#GP` (no I/O permission bitmap).
- A builder API (`PerCpuGdt::set_ist`, `set_privilege_stack`,
  `finalize`) that validates every input — IST indices in `1..=7`,
  stack tops non-null and 16-byte aligned — and surfaces violations as
  `IstError` rather than panicking (AGENTS.md §2.9).
- A bare-metal `unsafe fn install(&'static mut self)` (gated behind
  `cfg(all(target_arch = "x86_64", target_os = "none"))`) that
  executes `lgdt`, reloads DS/ES/FS/GS/SS with the kernel data
  selector, reloads CS via a far return, and loads the TR with `ltr`.
  Every invariant the asm relies on (`'static` storage, finalized TSS
  descriptor, register clobbers) is documented in the `# Safety`
  block; the host unit tests below cover the non-asm portions
  exhaustively.

Host coverage (35 tests touching `gdt` directly):

- Every code/data descriptor's bit pattern is asserted against the SDM
  figures (`P`, `DPL`, `S`, `Type`, `L`).
- The 64-bit TSS descriptor splitter (`tss_descriptor`) is verified to
  scatter `base[0..64]` and `limit[0..20]` across the eight legacy
  fields, and to clamp a misuse-supplied `dpl > 3` rather than smear
  into the `P` bit.
- `Tss` field offsets are pinned via `offset_of!` against the SDM
  §8.7 figures (`RSP0=0x04`, `IST1=0x24`, `IOPB=0x66`,
  `size_of::<Tss>() == 0x68`); a separate `const _` assertion makes
  any struct edit that desyncs `TSS_BYTE_LEN` fail compilation.
- All four `IstError` paths are reached by negative tests.

### Stage 3a (c1) — per-CPU bring-up wired into the QEMU stress test

This slice integrates the `gdt` primitives above with the new
`interrupts` and `context` modules behind a single
`unsafe fn percpu::init(cpu_index)` entry point. Each CPU calls
`rustos_arch_x86_64::percpu::init` exactly once during bring-up.

| Piece | Source |
|---|---|
| `PerCpu` bundle (per-CPU GDT + IDT + IST stacks), `init`, `MAX_CPUS = 16`, `IST_STACK_BYTES = 16 KiB`, IST index constants | `kernel/arch/x86_64/src/percpu.rs` |

Properties:

- The arena is a single `static mut PER_CPU: [PerCpu; MAX_CPUS]` in
  `.bss`; no allocator is involved. `MAX_CPUS = 16` is the source of
  truth and is cross-asserted against
  `tests/integration/scheduler_stress_qemu/src/kernel.rs::MAX_CPUS` by
  a `const _: () = assert!(…)` in the test crate.
- IST 1 is reserved for `#DF` (Double Fault, vector 8), IST 2 for
  `#NMI` (vector 2); both stacks are 16 KiB and 16-byte aligned by
  virtue of `#[repr(C, align(16))]` on `PerCpu`.
- A per-CPU `AtomicBool` latch (`PER_CPU_INITIALISED`) makes a second
  call for the same index return `InitError::AlreadyInitialised`
  rather than re-installing a half-mutated table.
- After `init` returns the per-CPU GDT is `lgdt`-installed (CS/DS
  reloaded, `ltr` issued) and the per-CPU IDT is `lidt`-installed
  with every vector routed through the common ISR prologue
  (fail-closed by default).

The `scheduler_stress_qemu` integration test now calls
`percpu::init(0)` at the very top of `kernel_main` and
`percpu::init(cpu_id as usize)` at the very top of each AP's
`ap_entry`. The trampoline-internal GDT is therefore live only between
SIPI delivery and the AP's first Rust instruction; from then on each
AP is on its own real per-CPU descriptor tables.

### Stage 3a (c2) — common ISR prologue

| Piece | Source |
|---|---|
| `InterruptStackFrame`, `SavedRegs`, `IdtEntry`, `Idt`, `IdtPointer`, `Idt::load`, `Idt::with_default_handler` | `kernel/arch/x86_64/src/interrupts.rs` |
| Common ISR prologue (`rustos_arch_x86_64_isr_default`) | `kernel/arch/x86_64/src/interrupts.s` |

What lands:

- The CPU-pushed `InterruptStackFrame` (`rip`, `cs`, `rflags`,
  `rsp`, `ss`) is exposed as a `#[repr(C)]` struct with `offset_of!`
  pinned host tests against Intel SDM Vol 3A §6.14.2.
- The prologue's `SavedRegs` block (15 GPRs in push-descending
  order, `r15` at offset 0 through `rax` at offset `14*8`) is the
  Rust mirror of the assembly push sequence; layout is locked by a
  `const _: () = assert!(size_of == 15 * 8);` and by an `offset_of!`
  host test.
- `IdtEntry::interrupt_gate(handler, selector, ist)` builds a 64-bit
  interrupt gate (type `0x8E`, DPL 0) and the constructor masks `ist`
  to three bits so an attacker-controlled IST index cannot smear into
  `type_attr` (host tests `interrupt_gate_splits_handler_address` and
  `interrupt_gate_masks_ist_to_3_bits`).
- `Idt::with_default_handler(handler, selector, ist_for_exception)`
  populates all 256 slots in a single call; the caller-supplied
  closure picks an IST for each architectural exception
  (`percpu::init` uses it to wire vector 8 → IST 1, vector 2 → IST 2,
  every other slot → IST 0).
- The assembly prologue saves all 15 GPRs in the documented order,
  loads `rdi` with a pointer to the on-stack `SavedRegs`, aligns the
  stack to System V AMD64 §3.2.2, and calls
  `rustos_arch_x86_64_default_interrupt`. The Rust callee is
  `cfg(target_os = "none")` and `-> !`; it halts the binary via
  `qemu_exit::exit_failure` per AGENTS.md §10 (fail closed on every
  unexpected interrupt). Per-vector ISRs are deferred to the
  (c5) preemption commit, which will extend this surface via a
  `define_isr!` macro rather than expanding the default thunk.

### Stage 3a (c3) — context-switch primitive

| Piece | Source |
|---|---|
| `TaskCtx`, `TaskCtx::prepare`, `PrepareError`, `switch` (safe wrapper) | `kernel/arch/x86_64/src/context.rs` |
| `extern "C" fn rustos_arch_x86_64_switch(prev, next)` | `kernel/arch/x86_64/src/context.s` |

What the new `context` module provides:

- `TaskCtx { rsp: u64 }` — the per-task register-save area, layout
  pinned by `size_of` and `offset_of!` const-assertions so the
  assembly can address the `rsp` field via the constant offset
  `0x00(%rdi)` / `0x00(%rsi)`.
- `TaskCtx::prepare(stack_top, entry, arg)` synthesises the eight-
  qword resume frame the assembly's epilogue pops on first-run:
  `r15, r14, r13, r12, rbx, rbp = 0; rdi = arg; ret = entry`.
  The function rejects null / misaligned / too-small stacks
  (`PrepareError::{NullStack, Misaligned, TooSmall}`).
- The assembly side `rustos_arch_x86_64_switch` pushes the six
  callee-saved registers (`rbx, rbp, r12..r15`) plus `rdi` onto the
  outgoing task's kernel stack, records the resulting `rsp` into
  `(*prev).rsp`, loads `(*next).rsp`, pops the saved registers, and
  `ret`s. Pushing `rdi` unconditionally is what lets the same epilogue
  serve both a never-run task (whose synthesised frame holds the
  first-run argument in `rdi`) and a previously-suspended task.
- Caller-saved registers (`rax, rcx, rdx, rsi, r8..r11`) are deliberately
  *not* preserved: by System V AMD64 §3.2.1 they carry no live state
  across a `call` boundary. The `switch` symbol is reached only through
  a `call`, so no host-task code can observe a clobber.
- The bare-metal `switch` is gated behind `cfg(target_os = "none")`;
  host tests cover the `TaskCtx::prepare` frame layout in detail
  (`prepare_writes_initial_frame` reads back the eight qwords through
  a real, suitably-aligned stack arena).

### Stage 3a (c4) — scheduler preemption surface

`kernel/sched` gained a single new entry point in this slice:
`Scheduler::on_timer_tick(cpu)` (plus the observable counters
`Scheduler::preemption_count(cpu)` and
`Scheduler::total_preemption_count`). The arch port's timer ISR
calls `on_timer_tick` after acknowledging the device-level
interrupt source; the scheduler increments a per-CPU `AtomicU64`
counter (`Relaxed`-bumped) and returns. It does **not** itself call
`Scheduler::step` — the task registry `RwLock` and the overflow
`SpinLock` are explicitly forbidden from interrupt context by
`kernel/sync`, so the cooperative `step` loop driven from kernel-
thread context remains the only writer of run-queue state. The
counter is the regression catcher; a future commit that lands
IRQ-safe locks can extend the entry point to drive a real
preemption step without changing the public signature.

The `SchedulerArch` trait is **not** extended in (c4). `send_ipi`
already documents the scheduler-asks-arch direction; the
arch-into-scheduler timer path is, by construction, a method on the
scheduler type and not on the arch trait (`AGENTS.md` §2.4 — no
interface creep, §15.5 — no parallel "convenience" method when the
existing one already covers the semantics).

The counter is the regression catcher Stage 2 lacked: a silent
revert to cooperative-only scheduling would keep the workload-
correctness invariants intact while breaking the security model
(`AGENTS.md` §5 — a runaway task on one CPU must not be able to
indefinitely block another). The `scheduler_stress_qemu`
integration test asserts `preemption_count(cpu) >= 10` per CPU at
the end of the workload; the threshold is intentionally well below
the >100 ticks per CPU a real run sees, so the assertion is
robust against QEMU TCG jitter without being a no-op.

### Stage 3a (c5) — LAPIC-timer-driven preemption

The arch crate's new `preempt` module wires the LAPIC timer into the
scheduler's `on_timer_tick` entry:

- **`define_isr!` macro** in `interrupts.rs` emits one `#[naked]`
  `extern "C" fn` per ISR. The body inlines the same 15-GPR push /
  16-byte stack align / call / 15-GPR pop / `iretq` sequence the
  default thunk in `interrupts.s` uses, but parameterised on the
  dispatcher symbol via `sym`. Vectors that push a hardware error
  code (`8`, `10`–`14`, `17`, `21`) are out of scope for the macro;
  they need a dedicated stub.
- **`preempt::TIMER_VECTOR = 0x20`** is the first user-installable
  IDT slot (Intel SDM Vol 3A §6.3.1) and the only consumer of the
  macro in this slice.
- **`preempt::rustos_arch_x86_64_timer_dispatch`** (the Rust
  trampoline the macro-emitted ISR stub calls) reads the LAPIC ID
  via a single MMIO read, maps it to the scheduler's dense `CpuId`
  through a 256-entry `LAPIC_TO_CPU_ID` table populated at bring-up
  time, invokes the installed callback, and writes `0` to the LAPIC
  EOI register. EOI is performed *after* the callback so a second
  tick cannot stack on the in-service bit; the callback runs with
  `IF = 0` (CPU clears it on interrupt-gate delivery), so the
  dispatcher itself is non-re-entrant by construction.
- **`preempt::init_local_preempt(cpu_index, &mut lapic, calibration)`**
  installs the timer ISR into the per-CPU IDT via the new
  `percpu::install_vector` (which writes a `volatile` `IdtEntry`
  through a raw-pointer cast — the CPU re-reads the IDT base on
  every delivery, so an entry overwrite while `IF = 0` is safe) and
  programs the LAPIC timer in periodic mode from the BSP-supplied
  `Calibration`.

Calibration on x86 derives from busy-waiting against the i8254 PIT
(`apic_timer::calibrate`), a single global device. Doing it
concurrently on every CPU would corrupt PIT channel 2. The
integration test therefore calibrates exactly once on the BSP and
APs re-use the result. This is correct on QEMU (one bus clock) and
on homogeneous single-package SMP Intel hardware; multi-socket
asymmetric hardware would need per-package re-calibration, which a
future commit can add behind the same `init_local_preempt` entry
point. The fail-loud cross-check is the per-CPU
`preemption_count >= 10` assertion in `scheduler_stress_qemu`.

What is *not* delivered yet (still tracked in `PLAN.md` Stage 3a
sub-checklist and in `.junie/next-session-prompt.md`):

- `kernel/core::KernelArch` impl wired into a new `rustos-kernel`
  binary (c7).
- Per-arch QEMU-runner module refactor in `tools/qemu` (d1).
- `PLAN.md` Stage 2 status block flip to `complete` (d2).

### Stage 3a (c6) — `syscall`/`sysret` entry

The `syscall_entry` module (`kernel/arch/x86_64::syscall_entry`)
owns the per-CPU machine state required to take a user-space
`syscall` instruction, marshal its register-passed arguments into
the architecture-neutral `rustos_kernel_syscall::RawArgs` layout,
and return to user space via `sysretq`. The architecture-neutral
dispatcher (validation, capability checks, audit) is owned by
`kernel/syscall` and is re-used verbatim — the arch port does not
duplicate the `SYSCALL_TABLE_HASH` validation surface
(AGENTS.md §2.2, §9).

The module is split along the same boundary as
`kernel/arch/x86_64::preempt`: pure host-testable MSR-value math
(`encode_star`, `efer_with_sce`, `fmask_value`, `pack_raw_args`),
per-CPU state (a fixed-size table of `SyscallTls` blocks, one per
CPU, each holding the kernel-stack top and a user-`%rsp` save
slot), and bare-metal pieces gated to `target_os = "none"` (the
naked `syscall_entry_stub`, its Rust trampoline
`rustos_arch_x86_64_syscall_dispatch`, and `init_local_syscalls`).
A `SyscallDispatchFn` callback (`set_dispatch_callback`) is the
single integration point with the binary's
`rustos_kernel_syscall::Dispatcher` — the (c7) binary commit is the
only writer of that callback.

`init_local_syscalls` programs five MSRs on the calling CPU
(Intel SDM Vol 3A §5.8.8, §2.7):

| MSR | Address | Purpose |
| --- | --- | --- |
| `IA32_EFER` | `0xC000_0080` | Set `SCE` (bit 0) to enable `syscall`/`sysret`. |
| `IA32_STAR` | `0xC000_0081` | Encode the kernel CS/SS pair (entry) and the user CS/SS triplet (sysret). |
| `IA32_LSTAR` | `0xC000_0082` | Linear address of `syscall_entry_stub`. |
| `IA32_FMASK` | `0xC000_0084` | Clear `IF`/`TF`/`DF`/`AC`/`NT`/`RF`/`VM` on entry (value `0x7_4700`). |
| `IA32_KERNEL_GS_BASE` | `0xC000_0102` | Per-CPU `SyscallTls` address (swapped in by `swapgs`). |

The naked `syscall_entry_stub`:

1. `swapgs` — `%gs` now points at this CPU's `SyscallTls`.
2. Save the user `%rsp` into `gs:8` and load the kernel `%rsp`
   from `gs:0`.
3. Push the user `RFLAGS` (`%r11`) and saved RIP (`%rcx`) plus a
   padding slot so the System V "rsp ≡ 0 (mod 16) at `call`" rule
   holds.
4. Build the `SYSCALL_MAX_ARGS`-wide argument array on the kernel
   stack from `rdi`/`rsi`/`rdx`/`r10`/`r8`/`r9`.
5. Call `rustos_arch_x86_64_syscall_dispatch` with `%rdi = syscall
   number` (the saved `%rax`) and `%rsi = &args[0]`.
6. Pop the args + saved registers + pad, restore the user `%rsp`,
   `swapgs`, `sysretq`.

The fail-closed posture is the same as the default ISR
(`interrupts::rustos_arch_x86_64_default_interrupt`): if a syscall
reaches the trampoline before the binary installed its dispatch
callback, the kernel exits the QEMU run with failure via
`qemu_exit::exit_failure` rather than returning an unspecified
value to user space (AGENTS.md §7).

`unsafe`-block accounting introduced by (c6) (all encapsulated
behind safe APIs and covered by host unit tests for the invariants
that are not the privileged instruction itself):

| Site | Justification |
| --- | --- |
| `install_kernel_rsp0` raw-pointer writes | Caller pins `cpu_index` to this CPU; no other CPU touches the slot. |
| `rdmsr` / `wrmsr` `asm!` blocks | CPL=0 + caller-validated MSR address + host-tested MSR value. |
| `init_local_syscalls` `wrmsr` sequence | Forwarded contract; each value is constructed by the host-tested encoders. |
| `dispatch_callback` / trampoline `transmute` | Every store into the callback slot round-trips a valid `SyscallDispatchFn` (mirrors `preempt::set_timer_callback`). |
| Naked `syscall_entry_stub` | Reachable only via the CPU's `syscall` instruction; the rustdoc spells out the entry/exit invariants. |

The five MSR encoders + the `SyscallTls` layout + the per-register
argument packing are covered by 10 host unit tests in
`syscall_entry::tests`; the bare-metal `wrmsr` and naked-entry
paths are exercised end-to-end by the (c7) binary commit's QEMU
integration test.

Each of these items is *individually* a multi-step kernel change
needing tests + rustdoc + docs updates in the same commit; landing
them in a single session would have forced shortcuts AGENTS.md §15
forbids. The continuation prompt enumerates them verbatim so the
next session can pick them up.

Four `// SAFETY:`-annotated `unsafe` regions are introduced by this
stage, all encapsulated behind safe APIs: the `core::arch::global_asm!`
that embeds the trampoline payload, the `read_volatile` of the LAPIC ID
register (`smp::bsp_lapic_id`), the byte-exact `copy_nonoverlapping`
from the assembled payload to physical `0x8000`
(`smp::TrampolineFrame::install`), and the `Acquire`-load of the
`ready` flag through an `AtomicU32` raw-pointer cast against the
in-frame bytes (`smp::TrampolineFrame::load_ready`).

## Running Stage 2 QEMU tests

> **Stage 3a (b)** moved `scheduler_stress` from host-only execution to
> a real `-smp 4` QEMU run via `tests/integration/scheduler_stress_qemu`.
> The host-side `tests/integration/scheduler_stress` workspace test is
> unchanged and remains green. **Stage 3a (c5)** swapped the
> cooperative step loop for real LAPIC-timer-driven preemption; the
> test now asserts a per-CPU preemption-count lower bound to catch a
> silent revert to cooperative scheduling.

### Prerequisites

The Stage-2 QEMU pipeline expects a Linux host with:

- The pinned RustOS nightly toolchain (see `rust-toolchain.toml`) plus the
  `x86_64-unknown-none` cross target.
- `qemu-system-x86_64` ≥ 8.0.
- `grub-mkrescue` and `xorriso` for building the boot ISO.
- The `ovmf` package for UEFI firmware (Debian/Ubuntu) or `edk2-ovmf`
  (Fedora/Arch). UEFI is used because most distributions ship only the
  EFI GRUB modules; the runner discovers OVMF via
  [`rustos_qemu::iso::find_ovmf`].

If any of these are missing, `cargo xtask test --qemu` exits with a clear
diagnostic naming the missing package (`AGENTS.md` §15.10 — no silent
skips, no flaky bypasses).

### Invocation

```text
cargo xtask test --qemu
```

This is the *only* sanctioned entry point. It:

1. Runs the standard `cargo test --workspace --all-targets --locked`
   pass first (host-side tests including the workspace-level
   `tests/integration/scheduler_stress`).
2. Builds each enrolled QEMU test for `x86_64-unknown-none`.
3. Wraps each kernel ELF in a GRUB-EFI ISO via
   `tools/qemu/src/iso.rs::build_grub_iso`.
4. Boots the ISO under QEMU with `-display none -serial stdio -cdrom`
   and the `isa-debug-exit` device on port `0xf4`.
5. Enforces the per-test strict wall-clock timeout. **No retries.**
   Timeout is a hard failure (`AGENTS.md` §7).

A passing run looks like:

```text
xtask: [test --qemu] 1 test(s) enrolled
xtask: [test --qemu (build rustos-test-memory-isolation)] cargo build ...
xtask: [test --qemu (run rustos-test-memory-isolation)] kernel=... cpus=1 timeout=60s
```

Failure modes are reported through `rustos_qemu::Outcome`:

- `Pass` — kernel wrote `0x10` to `0xf4`; `xtask test --qemu` exits 0.
- `Fail` — any other QEMU exit status; the captured serial transcript is
  printed verbatim.
- `Timeout` — `cargo xtask` errors out with the budget that was exceeded
  and the partial serial transcript.

### Manual debugging

For ad-hoc runs (e.g. while iterating on the boot trampoline) the
`rustos-qemu-run` binary is the same code path `xtask` uses:

```text
cargo build -p rustos-test-memory-isolation --target x86_64-unknown-none
cargo run -p rustos-qemu --bin rustos-qemu-run -- \
    --kernel target/x86_64-unknown-none/debug/rustos-test-memory-isolation \
    --timeout-secs 60
```

Set `RUSTOS_QEMU_DEBUG=1` to print the exact QEMU invocation the runner
constructs.

## Stage 3a (d1) — Per-arch QEMU runner module

Stage 3a (d1) moved the x86_64-specific defaults out of the generic
`tools/qemu::Spec` into a dedicated `tools/qemu/src/x86_64.rs` module.
The split is internal — the two existing integration tests
(`tests/integration/memory_isolation`,
`tests/integration/scheduler_stress_qemu`) and the
`cargo xtask test --qemu` driver use the same `Spec::for_x86_64_kernel`
/ `with_cpus` / `with_timeout` / `Runner::run` entry points as before —
but it lines the codebase up for Stage 3b/3c/3d, which will add
`tools/qemu/src/aarch64.rs`, `riscv64.rs`, and `wasm32.rs` without
touching the generic [`Spec`] (`AGENTS.md` §2.4 — no interface creep).

| Surface | Module |
|---|---|
| `Outcome`, `Arch`, `Spec`, `Runner` | `tools/qemu/src/lib.rs` (architecture-neutral) |
| `DEFAULT_RAM_MIB`, `ISA_DEBUG_EXIT_IOPORT/IOSIZE`, `QEMU_BINARY`, OVMF/UEFI argv assembly, GRUB-EFI ISO build dispatch | `tools/qemu/src/x86_64.rs` |
| `build_grub_iso`, `find_ovmf` | `tools/qemu/src/iso.rs` (architecture-neutral; called by the x86_64 backend) |

The argv contract — `-no-reboot`, `-display none`, `-serial stdio`,
`-m {DEFAULT_RAM_MIB}M`, `-smp {spec.cpus}`,
`-device isa-debug-exit,iobase=0xf4,iosize=0x4`, the OVMF pflash pair
in the documented order, and `-cdrom {iso}` — is asserted by eight new
host unit tests in `tools/qemu/src/x86_64.rs::tests`. Those tests use a
pure `build_argv` helper that takes a fake `OvmfPaths` so they run on
hosts without the `ovmf` package installed (the OVMF-discovery step
itself is still covered by the `rustos_qemu::iso::find_ovmf` site).

The top-level `ISA_DEBUG_EXIT_IOPORT` / `ISA_DEBUG_EXIT_IOSIZE`
constants are now thin re-exports of the per-arch ones, with a unit
test (`tests::isa_debug_exit_constants_match_x86_64_module`) that
fails closed if the two halves drift apart — the kernel side
(`kernel/arch/x86_64::qemu_exit`) hard-codes the same numeric values
and a silent drift would silently break the Pass/Fail protocol.
