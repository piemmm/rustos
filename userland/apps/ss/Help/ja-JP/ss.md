## NAME

ss — 開いているソケットを一覧する

## SYNOPSIS

`ss [option...]`

## DESCRIPTION

システムの開いているソケットを、ソケットごとに 1 行で一覧します。
トランスポートプロトコル、接続状態、受信・送信キューの深さ、ローカルと
相手の `address:port`、そして（`-p` を付けると）所有プロセスを示します。

各行はシステム情報 API のソケット一覧に由来し、ネットワークスタックは
これを特権かつ監査付きの問い合わせとして応答します。各プリンシパルの
ソケットと各接続の相手を明かすため、すべてのソケットの一覧には
`CAP_SYSINFO_GLOBAL` が必要です。`/proc/net` は存在しません。その能力を
持たないセッションにはその旨が伝えられ、空の表を印字する代わりに `ss`
は終了します。

既定では、接続済みで待ち受けていないソケットを表示します。`-l` は待ち
受けソケットのみ、`-a` は両方を表示します。隠された待ち受け数は標準情報
ストリーム（fd 3）に記録され、表には決して書きません。`-t` と `-u` は
プロトコルを、`-4`/`-6` はアドレスファミリを絞ります。いずれも指定
しなければ、すべてのプロトコルとファミリを表示します。ポートは常に数値
です（TAIRiX にはサービス名データベースがありません）から、`-n` は受け
付けますがポートには常に有効です。アドレスも、`-r` がホスト名を求めない
かぎり数値です。`-r` は各アドレスをシステムのスタブリゾルバで解決し
（`PTR` 問い合わせ）、異なるアドレスごとに一度だけ問い合わせ、名前のない
アドレスは数値のままにします。未指定のアドレスは `*`、未バインドのポート
は `*` と印字します。IPv6 アドレスは角括弧で囲み、`:port` 区切りが曖昧に
ならないようにします。解決した名前に角括弧は要りません。

`ss` はオプションのみを受け付けます。iproute2 のフィルタ式文法（状態と
アドレスのフィルタ）は未実装なので、裸のオペランドは黙って無視される
引数ではなく使用法の誤りです。

## OPTIONS

- `-t, --tcp` — TCP ソケットを表示する。`-t` も `-u` もなければ両方の
  プロトコルを表示する。
- `-u, --udp` — UDP ソケットを表示する。
- `-a, --all` — 待ち受けと接続済みのソケットを表示する。
- `-l, --listening` — 待ち受けソケットのみ表示する。
- `-n, --numeric` — サービス名を解決しない。TAIRiX では常に有効。
  慣れのために受け付ける。ホスト名は `-r` の担当。
- `-r, --resolve` — アドレスを DNS でホスト名に解決する。既定では
  無効なので、求めないかぎり一覧は問い合わせを出さない。
- `-p, --processes` — 所有プロセスの列（`pid=N`）を加える。
- `-4, --ipv4` — 一覧を IPv4 ソケットに絞る。
- `-6, --ipv6` — 一覧を IPv6 ソケットに絞る。
- `-H, --no-header` — 見出し行を抑制する。
- `-s, --summary` — ソケット表の代わりに、スタック全体の TCP 接続防御の
  集計を表示する。
- `-?, --help` — このコマンド自身の簡易ヘルプを表示する。

## EXAMPLES

- `ss` — 接続済みで待ち受けていないソケット。
- `ss -a` — 待ち受けと接続済みのすべてのソケット。
- `ss -l` — 待ち受けソケットのみ。
- `ss -tlp` — 待ち受け中の TCP ソケットと所有プロセス。
- `ss -u4` — IPv4 上の UDP ソケット。
- `ss -r` — 同じ一覧を、アドレスをホスト名に解決して表示。

## EXIT STATUS

- `0` — 一覧を生成した（または簡易ヘルプを書き出した）。
- `1` — ソケットの問い合わせが拒否または失敗した、あるいは出力を書け
  なかった。
- `2` — コマンド行を解釈できなかった。

## ENVIRONMENT

- `LANG` — 簡易ヘルプに用いる優先ロケール（`fr-FR` のような BCP-47
  タグ）。
