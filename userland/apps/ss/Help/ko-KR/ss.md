## NAME

ss — 열린 소켓 목록 보기

## SYNOPSIS

`ss [option...]`

## DESCRIPTION

시스템의 열린 소켓을 소켓마다 한 행씩 나열합니다. 전송 프로토콜, 연결
상태, 수신·송신 큐 깊이, 로컬과 상대의 `address:port`, 그리고 (`-p`와
함께) 소유 프로세스를 보여 줍니다.

각 행은 시스템 정보 API의 소켓 목록에서 나오며, 네트워크 스택은 이를
특권이며 감사되는 질의로 응답합니다. 각 주체의 소켓과 각 연결의 상대를
드러내므로, 모든 소켓을 나열하려면 `CAP_SYSINFO_GLOBAL`이 필요합니다.
`/proc/net`은 없습니다. 그 권한이 없는 세션에는 그 사실이 통지되고 `ss`는
빈 표를 출력하는 대신 종료합니다.

기본적으로 목록은 연결된, 수신 대기가 아닌 소켓을 보여 줍니다. `-l`은
수신 대기 소켓만, `-a`는 둘 다 보여 줍니다. 숨겨진 수신 대기 수는 표준
정보 스트림(fd 3)에 기록되며 표에는 결코 쓰지 않습니다. `-t`와 `-u`는
프로토콜을, `-4`/`-6`은 주소 계열을 제한합니다. 아무것도 주지 않으면
모든 프로토콜과 계열을 보여 줍니다. 포트는 항상 숫자입니다
(TAIRiX에는 서비스 이름 데이터베이스가 없습니다). 따라서 `-n`은 받아
들이지만 포트에는 항상 적용됩니다. 주소도 `-r`이 호스트 이름을 요구하지
않는 한 숫자입니다. `-r`은 각 주소를 시스템 스텁 리졸버로 해석하고
(`PTR` 조회), 서로 다른 주소마다 한 번만 조회하며, 이름이 없는 주소는
숫자로 남겨 둡니다. 지정되지 않은 주소는 `*`로, 묶이지 않은 포트는
`*`로 출력합니다. IPv6 주소는 대괄호로 감싸 `:port` 구분자가 모호해지지
않게 합니다. 해석된 이름에는 대괄호가 필요 없습니다.

`ss`는 옵션만 받습니다. iproute2의 필터 표현식 문법(상태와 주소 필터)은
구현되지 않았으므로, 벌거벗은 피연산자는 조용히 무시되는 인자가 아니라
사용법 오류입니다.

## OPTIONS

- `-t, --tcp` — TCP 소켓을 보인다. `-t`도 `-u`도 없으면 두 프로토콜을
  모두 보인다.
- `-u, --udp` — UDP 소켓을 보인다.
- `-a, --all` — 수신 대기와 연결된 소켓을 보인다.
- `-l, --listening` — 수신 대기 소켓만 보인다.
- `-n, --numeric` — 서비스 이름을 해석하지 않는다. TAIRiX에서는 항상
  적용된다. 친숙함을 위해 받아들인다. 호스트 이름은 `-r`의 몫이다.
- `-r, --resolve` — 주소를 DNS로 호스트 이름으로 해석한다. 기본은
  꺼짐이므로, 요청하지 않으면 목록은 조회를 보내지 않는다.
- `-p, --processes` — 소유 프로세스 열(`pid=N`)을 더한다.
- `-4, --ipv4` — 목록을 IPv4 소켓으로 제한한다.
- `-6, --ipv6` — 목록을 IPv6 소켓으로 제한한다.
- `-H, --no-header` — 머리글 행을 억제한다.
- `-s, --summary` — 소켓 표 대신 스택 전체의 TCP 연결 방어 합계를
  출력한다.
- `-?, --help` — 이 명령 자체의 짧은 도움말을 보인다.

## EXAMPLES

- `ss` — 연결된, 수신 대기가 아닌 소켓.
- `ss -a` — 수신 대기와 연결된 모든 소켓.
- `ss -l` — 수신 대기 소켓만.
- `ss -tlp` — 수신 대기 중인 TCP 소켓과 소유 프로세스.
- `ss -u4` — IPv4 위의 UDP 소켓.
- `ss -r` — 같은 목록을 주소를 호스트 이름으로 해석해 보여 준다.

## EXIT STATUS

- `0` — 목록을 만들었다(또는 짧은 도움말을 썼다).
- `1` — 소켓 질의가 거부되거나 실패했다, 또는 출력을 쓸 수 없었다.
- `2` — 명령행을 이해하지 못했다.

## ENVIRONMENT

- `LANG` — 짧은 도움말에 선호하는 로캘(`fr-FR` 같은 BCP-47 태그).
