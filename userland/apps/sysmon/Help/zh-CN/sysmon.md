## NAME

sysmon — 实时观察内核的内存、缓存与负载

## SYNOPSIS

`sysmon [-d 秒.十分之一] [-h | -?]`

## DESCRIPTION

`sysmon` 是内核如何使用内存与 CPU 的全屏实时视图，全部通过系统信息 API 读取
——没有 `/proc` 可供抓取。它显示物理内存及其构成、内核堆、内存压力带及其近期
历史、可回收缓存账簿及其每类的**命中率**、`ramzip` 压缩层、固定内存总量、已挂
载卷的存储使用量、每个 CPU 的负载、内核中断表以及进程普查。系统在刻意施加负载
时它仍可用，空闲时在两次刷新之间休息（读取会驻留；它从不空转）。

启动时，监视器固定自身的内存（`mem_pin`，需要 `CAP_MEM_PIN`），以便在它所观察
的同一压力下永不因自身的缺页而停滞。被拒绝的固定会在标题行报告，会话继续但未
固定——固定是附带的，绝非致命。

显示在每个间隔刷新（除非 `-d` 改变，否则为 3.0 秒）。监视器不接受操作数：它由会
话内按下的键控制。

- `q` —— 退出。
- 左 / 右（或 `p`）—— 切换详情面板（左 = 上一个，右 / `p` = 下一个）：缓存、压缩
  层、已挂载卷的存储（磁盘）、每个 CPU 的负载、中断线、进程。
- `r` —— 立即刷新。
- `+` / `-` —— 将间隔延长 / 缩短一秒，介于 0.1 与 60 秒之间。
- 上/下、上翻页/下翻页、Home/End —— 滚动聚焦的面板。
- `h`、`?` —— 显示或隐藏会话的按键概要（它重现下方的条形图图例）。

### 概要块

一个固定的概要块位于详情面板之前。每行左侧都有标签，因此无需颜色也能读懂；颜色
仅作强化。

- **标题行** —— 工具名称、系统运行时间（`up D days, H:MM`）、三项负载平均值（1/5/15
  分钟）以及固定状态（`[pinned]`，或在固定被拒绝时为 `[unpinned: <reason>]`）。
- **`Mem`** —— 内存条（见条形图图例），其后是已用 / 总计 MiB、已用百分比、内核堆
  大小，以及——非零时——`ramzip` 压缩存储和 `pinned` 固定内存的数值。
- **`Pres`** —— 内存压力条：一个五带指示器，每个进入的带以其自身的严重度颜色填充，
  其后是当前带名、空闲 / 保留数值以及进入带的总次数。
- **`Hist`** —— 压力带历史条带：每次刷新一个字形，最旧的在左侧，每个按其带着色——
  `.` 正常、`-` 轻微、`=` 中等、`#` 严重、`!` 危急——因此一段压力读作一串彩色。
- **`CPU`** —— 汇总的 CPU 条（见条形图图例），其后是全部 CPU 的忙碌百分比、CPU 数
  量以及上下文切换与抢占计数的合计。
- **`Tasks`** —— 进程普查：总数、运行中、睡眠、已停止与僵尸计数（当全进程普查被拒
  绝而仅统计调用者自身任务时，附加 `(own)`）。
- **面板标签栏** —— 每个详情面板，聚焦者高亮；当聚焦面板溢出时，右侧带一个滚动指
  示器。

### 条形图图例

`Mem` 与 `CPU` 计量表是带方括号 `[…]` 的条。`?` 概要在运行中的会话内重现此图例。

内存条（`Mem`）是一个**堆叠**条，其单元命名物理内存所容纳之物——对已用内存的一个
*不相交*划分（`used` 即 `total` 减 `free`），因此没有任何东西被重复计数，且填充宽
度恰为已用比例：

- `#` —— 用户驻留内存（绿色）：驻留在用户地址空间中的页。
- `K` —— 内核堆（青色）：内核自身的堆与 slab。
- `=` —— 其他在用内存（品红）：一切在用但未在上面归类之物（页缓存、缓冲区、内核
  帧）。
- 空白 —— 空闲内存。

`ramzip` 压缩存储与 `pinned` 匿名内存与那些桶重叠（固定页是用户驻留的；压缩存储是
内核内存），因此它们作为条旁的数值报告，而非会重复计数的独立段——诚实的核算胜过误
导的图景。

压力条（`Pres`）按深度为每个带着色：正常/轻微绿色、中等黄色、严重/危急红色。

CPU 条（`CPU`）以忙碌单元 `#` 填充于空白的空闲轨道之上，按忙碌份额着色（低于 60 %
绿色、低于 85 % 黄色、85 % 及以上红色）。TAIRiX 仅将 CPU 时间核算为忙碌与空闲——API
中没有用户/系统/等待 I/O 的划分——因此该条显示单一诚实的忙碌类别，逐核细节在 `cpu`
面板中。

### 详情面板

左 / 右（或 `p`）遍历六个面板。每个都有一个反转的列标题（反显、加粗），以便标题读
作正文之上的一个独立条。

### caches —— 可回收缓存账簿

这些是内核可以交还以缓解内存压力而**不丢失数据**的缓存：每一条目都可从其规范来源重
建，因此内核将其丢弃而非换页。该面板直接回答“缓存是否在尽职？”：每行是一个回收类
别，跨所有已注册缓存聚合，并带有其自身的**命中率**。

各列：

- `class` —— 回收类别（见下方类别列表）。
- `entries` —— 当前为该类别持有的活动条目。
- `cached` —— 该类别的驻留占用：条目有效负载加上每条目的核算元数据，合计。
- `hits` —— 自启动以来从缓存服务的该类别查找（缓存避开了规范来源）。
- `misses` —— 自启动以来落到规范来源的该类别查找。
- `hit%` —— 缓存有效性比率，`hits / (hits + misses)` 取整数百分比。高比率意味着缓存
  值回其内存；低比率意味着它占着内存却没有省下工作。对于本次启动没有任何查找的类别
  （空闲分母），它读作 `-`，绝不读作捏造的 `0%`。
- `ref` —— 自启动以来被**拒绝**的准入（缓存拒绝持有的一条目：超预算、无法核算或内存
  不足）。
- `shr` —— 自启动以来由压力强制、回收了该类别条目的**收缩**遍历。
- `fail` —— 归于该类别的内部**故障**：一个检测到的账簿缺陷使某缓存中毒（以 fail-closed
  方式禁用）。

计数在超过 99 999 时缩写为 `k`/`M`/`G`/`T`（十进制千，而非 KiB），以使一列永不变宽。

各回收类别，按内核在压力下回收它们的顺序（列在最前者最先丢弃，因此列在靠后的缓存存
活最久）：

- `disposable-ui` —— 可丢弃的界面状态（栅格化资源、字形图集、窗口快照）：最廉价可失，
  最先离去。
- `predictive-prefetch` —— 投机性预取的数据（列表、缩略图、补全索引）：对正确性从不
  必需。
- `background-validation` —— 空闲时验证工作的产物（扫描进度、候选指纹）：投机性工作
  一旦压力开始便停止。
- `semantic-app-cache` —— 已验证的应用启动状态（已解析的清单、验证摘要、命令解析结
  果）。回收它绝不会使应用无法启动——加载闸门只是重新运行。
- `runtime-cache` —— 运行时拥有的派生状态（加载器准备、资源映射）：与语义缓存归为
  一组。
- `clean-file-data` —— 干净、可重建的文件*内容*，可从卷重新读取：一次有界的设备读取
  即可重建一个块。在任何东西被压缩进 `ramzip` 之前被回收。
- `transform-cache` —— 已授权数据的昂贵中间形态（经验证、解密、解压的簇数据）：比一
  次干净读取更昂贵地重建，因此在干净文件数据之后被回收。
- `fs-metadata` —— 文件系统元数据：stat 记录、名称查找结果、目录条目与安全记录。小、
  热且仅由多步树遍历重建，因此在压力下比文件数据存活更久。
- `reliability-assist` —— 可重建的恢复辅助状态（验证窗口、健康摘要）：以恢复延迟为
  正当理由，因此保留最久。

### ramzip —— 压缩内存层

`ramzip` 将冷的匿名页压缩进 RAM 中一个更小的存储，而不是将其换页。它的各节：

- `tier` —— 活动占用：持有的 `entries`、所表示的 `logical`（未压缩）字节、实际持有的
  `stored`（密文）字节与 `metadata` 核算字节；然后是 `saved`（逻辑减存储）及其占逻辑
  的百分比——该层赢回的内存。
- `capacity` —— 该层据以定尺的派生上限：`min`（始终可用）、`soft`（目标）、`hard`
  （天花板）以及当前的 `pinned` 字节。
- `compress` —— 存储（写入）路径：提供的 `attempts`、`accepted` 并存储，以及**接受率**
  （已接受 / 尝试）——本层自身的压缩命中率。其下是拒绝分解：不可压缩、策略、上限、不合
  格、保留、任务份额与颠簸拒绝。
- `restore` —— 取回（读取）路径：页 `faults`、`warm` 恢复、`clustered` 恢复及其合计
  `restored`；然后是 `failures`（认证 / 解码）与**成功率**（已恢复 / (已恢复 + 失败)）。
  每个比率都是一个百分比，或对空闲分母为 `-`。
- `warm-up` —— 后台热恢复器的 `attempts`、其 `stopped` 计数与其 `thrash-detected`
  计数。

### disks —— 已挂载卷的存储

每个已挂载卷一行 `df` 风格：挂载点、文件系统类型、总大小、已用、可用、使用百分比以
及一个 ASCII 使用条。驱动程序不报告容量的卷显示 `capacity unknown`，而非捏造的大小；
意外移除或恢复冲突的卷以警示呈现绘制并标注（`[unavailable-dirty]`、
`[unavailable-lost]`、`[recovery-conflict]`）。API 中没有每设备的 I/O 吞吐量计数器，因
此这里是诚实的容量与使用量，而非捏造的传输速率。

### cpu —— 每个 CPU 的负载

每个 CPU 一行：其在该间隔内的忙碌份额（`busy%`）、其运行队列深度（`queue`）以及其自
启动以来的上下文切换（`switches`）与抢占（`preemptions`）计数。

### irqs —— 中断线

每条已绑定的中断线一行，按线号升序：线的 id、拥有它的驱动任务（`owner`）、自启动以来
的中断 `count` 以及线的 `state`——`active`，或在内核对失控线的安全网将其禁用时为
`quarantined`（以警示呈现绘制）。

### procs —— 进程普查

按 `%cpu` 和按内存（`size`）的最大消耗者，各自带有其 pid、命令以及——对内存表——其状
态。完整的交互式进程列表是 `top` 的职责；这里只是普查摘要。

### 能力

每个数字都经由系统信息 API 传递。内核范围的统计查询（内存、压力、缓存、`ramzip`、每
个 CPU 的负载）需要 `CAP_SYSINFO_KERNEL`；中断线面板需要 `CAP_SYSINFO_HW`；全进程普查
需要 `CAP_SYSINFO_GLOBAL`。缺少其中之一的调用者会看到该面板的拒绝被逐条说明——绝无捏
造的数字——而会话的其余部分继续（以失败关闭，优雅降级）。已挂载卷的存储不受门禁限制。

## OPTIONS

- `-d, --delay <seconds>` —— 自动刷新之间的间隔，以秒计，可带可选的小数（仅保留第一位
  小数，即十分之一）：`sysmon -d 1.5` 每 1.5 秒刷新。默认 3.0。GNU `top` 接受零间隔并尽
  可能快地刷新；TAIRiX 从不空转，因此零被抬升到 0.1 秒的最小值。
- `-h, -?` —— 显示此命令自身的简短帮助并退出。在运行中的会话内，同样的键改为切换按键
  概要。

## EXIT STATUS

- `0` —— 会话以 `q` 结束，或已显示简短帮助。
- `1` —— 终端失败；原因被打印到标准错误。
- `2` —— 命令行未能被理解。

## ENVIRONMENT

- `LANG` —— 简短帮助的首选区域设置（一个 BCP-47 标签，如 `zh-CN`）。
