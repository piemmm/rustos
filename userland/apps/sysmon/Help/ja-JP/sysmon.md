## NAME

sysmon — カーネルのメモリ・キャッシュ・負荷をライブで観察する

## SYNOPSIS

`sysmon [-d 秒.十分の一] [-h | -?]`

## DESCRIPTION

`sysmon` は、カーネルがメモリと CPU に対して何をしているかの全画面ライブ表示
で、すべてシステム情報 API を通して読み取られます——こそぎ取るための `/proc`
はありません。物理メモリとその構成、カーネルヒープ、メモリ圧迫帯とその最近の
履歴、クラスごとの**ヒット率**を伴う回収可能キャッシュ台帳、`ramzip` 圧縮層、
固定メモリの合計、マウント済みボリュームのストレージ使用量、CPU ごとの負荷、
カーネル割り込み表、そしてプロセスの人口調査を表示します。システムが意図的な
負荷の下にある間も使用可能なままで、アイドル時には更新の合間に休みます（読み
取りは待機します。決して空回りしません）。

起動時、モニタは自身のメモリを固定し（`mem_pin`、`CAP_MEM_PIN` を要する）、観察
しているまさにその圧迫の下で自身のページフォールトに決して行き詰まらないよう
にします。拒否された固定はタイトル行に報告され、セッションは固定なしで続行しま
す——固定は付随的であり、決して致命的ではありません。

表示は各間隔（`-d` が変えない限り 3.0 秒）で更新されます。モニタはオペランドを
取りません。セッション内で押されるキーで操作します。

- `q` — 終了する。
- 左 / 右（または `p`）— 詳細パネルを切り替える（左 = 前、右 / `p` = 次）：
  キャッシュ、圧縮層、マウント済みボリュームのストレージ（ディスク）、CPU ごとの
  負荷、割り込み線、プロセス。
- `r` — 今すぐ更新する。
- `+` / `-` — 間隔を 1 秒延ばす / 縮める。0.1 秒から 60 秒の間。
- 上/下、PageUp/PageDown、Home/End — 焦点のパネルをスクロールする。
- `h`、`?` — セッションのキー早見（下のバーの凡例を再現するもの）を表示または
  非表示にする。

### 要約ブロック

固定の要約ブロックが詳細パネルの前にあります。各行は左端にラベルが付いており、
色なしでも読めます。色は補強にすぎません。

- **タイトル行** — ツール名、システムの稼働時間（`up D days, H:MM`）、三つの負荷
  平均（1/5/15 分）、そして固定状態（`[pinned]`、または固定が拒否された場合は
  `[unpinned: <reason>]`）。
- **`Mem`** — メモリバー（バーの凡例を参照）、続いて使用中 / 合計 MiB、使用率、
  カーネルヒープの大きさ、そして——ゼロでないとき——`ramzip` 圧縮ストアと `pinned`
  固定メモリの数値。
- **`Pres`** — メモリ圧迫バー：五帯のゲージで、到達した各帯はそれ自身の重大度色
  で塗られ、続いて現在の帯名、空き / 予備の数値、帯への進入回数の合計。
- **`Hist`** — 圧迫帯の履歴ストリップ：更新ごとに一つの字形、最古が左端、各々が
  その帯で色付けされる——`.` 正常、`-` 軽微、`=` 中程度、`#` 重度、`!` 危機的——ので、
  圧迫のひと続きは色付きの連なりとして読めます。
- **`CPU`** — 集約 CPU バー（バーの凡例を参照）、続いて全 CPU の使用率、CPU 数、
  そしてコンテキストスイッチとプリエンプションの合計カウンタ。
- **`Tasks`** — プロセスの人口調査：合計、実行中、スリープ、停止、ゾンビの数
  （全プロセスの人口調査が拒否され、呼び出し元自身のタスクのみが数えられる場合は
  `(own)` が付加される）。
- **パネルタブバー** — 各詳細パネルで、焦点のものが強調され、焦点のパネルがあふ
  れるとき右端にスクロール指標が付きます。

### バーの凡例

`Mem` と `CPU` のゲージは角括弧 `[…]` で囲まれたバーです。`?` の早見が実行中の
セッション内でこの凡例を再現します。

メモリバー（`Mem`）は**積層**バーで、その各セルは物理メモリが何を保持している
かを名指しします——使用中メモリの*互いに素な*分割（`used` は `total` から `free`
を引いたもの）なので、何も二重に数えられず、塗られた幅はちょうど使用中の割合に
等しくなります：

- `#` — ユーザ常駐メモリ（緑）：ユーザアドレス空間に常駐するページ。
- `K` — カーネルヒープ（シアン）：カーネル自身のヒープとスラブ。
- `=` — その他の使用中メモリ（マゼンタ）：使用中だが上で帰属されないすべて（ページ
  キャッシュ、バッファ、カーネルフレーム）。
- 空白 — 空きメモリ。

`ramzip` 圧縮ストアと `pinned` 匿名メモリはそれらのバケツと重なる（固定ページは
ユーザ常駐であり、圧縮ストアはカーネルメモリ）ため、二重に数える別個のセグメント
としてではなく、バーの傍らの数値として報告されます——誤解を招く図よりも正直な会計
です。

圧迫バー（`Pres`）は各帯を深さで色付けします：正常/軽微は緑、中程度は黄、重度/危機
的は赤。

CPU バー（`CPU`）は空白のアイドルトラックの上に使用中セル `#` で満たされ、使用中の
割合で色付けされます（60 % 未満は緑、85 % 未満は黄、85 % 以上は赤）。TAIRiX は CPU 時間
を使用中対アイドルとしてのみ会計します——API にユーザ/システム/入出力待ちの分割は
ありません——ので、バーは単一の正直な使用中カテゴリを示し、コアごとの詳細は `cpu`
パネルにあります。

### 詳細パネル

左 / 右（または `p`）で六つのパネルを巡ります。各々は反転した列見出し（反転表示、
太字）を持ち、見出しが本体の上の独立したバーとして読めるようにします。

### caches — 回収可能キャッシュ台帳

これらは、カーネルがメモリ圧迫を和らげるために**データ損失なしに**返せるキャッ
シュです。各エントリはその正準な出所から再構築可能なので、カーネルはページアウト
する代わりに破棄します。このパネルは「キャッシュは仕事をしているか？」への直接の
答えです。各行は一つの回収クラスで、登録済みの全キャッシュにわたって集約され、それ
自身の**ヒット率**を持ちます。

各列：

- `class` — 回収クラス（下のクラス一覧を参照）。
- `entries` — そのクラスのために現在保持されている生存エントリ。
- `cached` — そのクラスの常駐フットプリント：エントリのペイロードとエントリごとの
  会計メタデータを合わせたもの。
- `hits` — 起動以来キャッシュから供給されたそのクラスの検索（キャッシュが正準な
  出所を回避した）。
- `misses` — 起動以来正準な出所へ落ちたそのクラスの検索。
- `hit%` — キャッシュ有効性の比率、`hits / (hits + misses)` を整数パーセントで。高い
  比率はキャッシュがそのメモリに見合っていることを、低い比率は仕事を回避せずに
  メモリを抱えていることを意味します。この起動で何も検索されなかったクラス（アイ
  ドルな分母）には、捏造の `0%` ではなく `-` と表示されます。
- `ref` — 起動以来**拒否された**受け入れ（キャッシュが保持を辞退したエントリ：予算
  超過、会計不能、またはメモリ不足）。
- `shr` — 起動以来そのクラスのエントリを回収した、圧迫に強いられた**縮小**パス。
- `fail` — そのクラスに帰属される内部**障害**：あるキャッシュを毒した（fail-closed
  で無効化した）検出済みの台帳欠陥。

カウントは 99 999 を超えると `k`/`M`/`G`/`T`（KiB ではなく十進の千）と略され、列が
決して広がらないようにします。

回収クラスは、カーネルが圧迫の下でそれらを回収する順（先頭に挙げたものが最初に
破棄されるので、一覧の下位のキャッシュが最も長く生き残る）で：

- `disposable-ui` — 使い捨ての UI 状態（ラスタ化アセット、字形アトラス、ウィンドウ
  スナップショット）：失うのが最も安く、真っ先に去る。
- `predictive-prefetch` — 投機的に先読みされたデータ（一覧、サムネイル、補完索引）：
  正しさには決して必要でない。
- `background-validation` — アイドル時の検証作業の産物（走査の進捗、候補指紋）：
  投機的作業は圧迫が始まると止まる。
- `semantic-app-cache` — 検証済みのアプリ起動状態（解析済みマニフェスト、検証要約、
  コマンド解決結果）。これを回収してもアプリを起動不能にすることは決してできない——
  ロードゲートが再実行されるだけ。
- `runtime-cache` — ランタイム所有の派生状態（ローダ準備、リソースマップ）：意味的
  キャッシュとまとめられる。
- `clean-file-data` — ボリュームから再読み取り可能な、きれいで再構築可能なファイル
  *内容*：一回の有界なデバイス読み取りが一塊を再構築する。`ramzip` へ何かが圧縮され
  る前に回収される。
- `transform-cache` — 認可済みデータの高価な中間形態（検証・復号・展開されたクラス
  タデータ）：きれいな読み取りより再構築が高価なので、きれいなファイルデータの後に
  回収される。
- `fs-metadata` — ファイルシステムのメタデータ：stat レコード、名前解決結果、ディレ
  クトリエントリ、セキュリティレコード。小さく、熱く、多段の木の走査でしか再構築
  されないので、圧迫の下でファイルデータより長く生き残る。
- `reliability-assist` — 再構築可能な回復支援状態（検証窓、健全性要約）：回復の遅延に
  よって正当化されるので、最も長く保たれる。

### ramzip — 圧縮メモリ層

`ramzip` は冷えた匿名ページをページアウトする代わりに RAM 内のより小さなストアへ
圧縮します。その各節：

- `tier` — 生存フットプリント：保持中の `entries`、表現される `logical`（非圧縮）
  バイト、実際に保持される `stored`（暗号文）バイト、`metadata` 会計バイト。続いて
  `saved`（論理から格納を引いたもの）とその論理に対する割合——この層が取り戻す
  メモリ。
- `capacity` — この層が自らを寸法取りする派生上限：`min`（常に利用可能）、`soft`
  （目標）、`hard`（天井）、そして現在の `pinned` バイト。
- `compress` — 格納（書き込み）経路：提示された `attempts`、`accepted` かつ格納、そし
  て**受理率**（受理 / 試行）——圧縮についてのこの層自身のヒット率。その下に拒否の
  内訳：非圧縮可能、方針、上限、不適格、予備、タスク持ち分、スラッシュ拒否。
- `restore` — 取り出し（読み取り）経路：ページ `faults`、`warm` 復元、`clustered`
  復元、それらの合計 `restored`。続いて `failures`（認証 / 復号）と**成功率**（復元 /
  (復元 + 失敗)）。各比率はパーセント、またはアイドルな分母には `-`。
- `warm-up` — 背景の温復元器の `attempts`、その `stopped` カウント、その
  `thrash-detected` カウント。

### disks — マウント済みボリュームのストレージ

マウント済みボリュームごとに `df` 風の一行：マウント点、ファイルシステム種別、
総サイズ、使用中、利用可能、使用率、そして ASCII の使用バー。ドライバが容量を報告
しないボリュームは、捏造したサイズではなく `capacity unknown` と表示します。不意に
取り外された、または回復競合のボリュームは警告の描出で描かれ、印が付きます
（`[unavailable-dirty]`、`[unavailable-lost]`、`[recovery-conflict]`）。API にデバイス
ごとの入出力スループットカウンタはないので、これは捏造した転送速度ではなく正直な
容量と使用量です。

### cpu — CPU ごとの負荷

CPU ごとに一行：その間隔にわたる使用中の割合（`busy%`）、その実行キューの深さ
（`queue`）、そして起動以来のコンテキストスイッチ（`switches`）とプリエンプション
（`preemptions`）のカウント。

### irqs — 割り込み線

束縛された割り込み線ごとに一行、線番号の昇順で：線の id、所有するドライバタスク
（`owner`）、起動以来の割り込み `count`、そして線の `state`——`active`、または暴走線に
対するカーネルの安全網がそれを無効化したときは `quarantined`（警告の描出で描かれ
る）。

### procs — プロセスの人口調査

`%cpu` ごとおよびメモリ（`size`）ごとの最大消費者で、各々その pid、コマンド、そして
——メモリ表については——その状態を伴います。完全な対話的プロセス一覧は `top` の仕事
です。これは人口調査の要約だけです。

### 能力

すべての数値はシステム情報 API を旅します。カーネル全体の統計クエリ（メモリ、圧迫、
キャッシュ、`ramzip`、CPU ごとの負荷）は `CAP_SYSINFO_KERNEL` を要します。割り込み線
パネルは `CAP_SYSINFO_HW` を要します。全プロセスの人口調査は `CAP_SYSINFO_GLOBAL` を
要します。いずれかを欠く呼び出し元は、そのパネルの拒否が説明されるのを見ます——捏造
した数値は決して見ません——一方でセッションの残りは続行します（閉じて失敗し、優雅
に劣化する）。マウント済みボリュームのストレージは門で制限されません。

## OPTIONS

- `-d, --delay <seconds>` — 自動更新の間隔で、秒単位、任意の小数付き（最初の小数一桁、
  すなわち十分の一だけが保たれる）：`sysmon -d 1.5` は 1.5 秒ごとに更新します。既定は
  3.0。GNU `top` はゼロ間隔を受け入れ、できる限り速く更新しますが、TAIRiX は決して
  空回りしないので、ゼロは 0.1 秒の最小へ引き上げられます。
- `-h, -?` — このコマンド自身の短いヘルプを表示して終了する。実行中のセッション内で
  は、同じキーが代わりにキー早見を切り替えます。

## EXIT STATUS

- `0` — セッションが `q` で終わった、または短いヘルプが表示された。
- `1` — 端末が失敗した。理由は標準エラーに出力される。
- `2` — コマンド行が理解されなかった。

## ENVIRONMENT

- `LANG` — 短いヘルプのための優先ロケール（`ja-JP` のような BCP-47 タグ）。
