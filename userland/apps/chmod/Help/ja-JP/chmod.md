## NAME

chmod — ファイルのモードビットを変更する

## SYNOPSIS

`chmod [-cfRv] [--] MODE file...`

## DESCRIPTION

各ファイルオペランドの許可ビットを順に `MODE` へ変更します。`MODE`
は、許可ビットを丸ごと置き換える絶対 8 進値（`644`、`0755` など）
か、ファイルの現在のビットを変換するコンマ区切りのシンボリック節
`[ugoa]*[-+=][rwxXst]*`（`g+w`、`o-rx`、`a=rx`、`u+s`）のいずれか
です。シンボリックの `X` は、ディレクトリか、すでに実行ビットを持つ
ファイルにのみ実行を与えます。

ファイルのモードを変更できるのは所有者だけです。カーネルはそれ以外
の全員を拒否し、capability を保持していても例外にはなりません。
`-R` を付けるとディレクトリオペランドを変更した後、その内容を再帰的
に変更します。最初の失敗で、以降のオペランドの前に実行が停止しま
す。`--` はオプション解析を終了し、以降の引数はすべてオペランドで
す。`-` で始まるモードは、ダッシュなしで書く（`a-w`）か、先にオプ
ションを終了してください（`chmod -- -w file`）。

## OPTIONS

- `-R, --recursive` — ファイルとディレクトリを再帰的に変更する。
- `-c, --changes` — モードが実際に変わったファイルだけを報告する。
- `-v, --verbose` — 処理したすべてのファイルを報告する。
- `-f, --silent, --quiet` — ほとんどのエラーメッセージを抑止する。
  実行は失敗のままで、終了コードがそれを報告する。
- `-h, -?, --help` — このコマンドの短いヘルプを表示する。

## EXAMPLES

- `chmod 644 notes.txt` — 所有者は読み書き、他は読み取りのみ。
- `chmod g+w shared.txt` — 現在のビットにグループの書き込みを追加。
- `chmod -R a=rx Docs` — `Docs` ツリーを全員が読めて辿れるように
  する。

## EXIT STATUS

- `0` — すべてのモード変更が成功した。
- `1` — ファイルシステムまたは出力の失敗。理由は標準エラーに出力
  される（`-f` では抑止）。
- `2` — コマンド行を解釈できなかったか、モードオペランドが 8 進で
  もシンボリックでもなかった。

## ENVIRONMENT

- `LANG` — 短いヘルプに使う優先ロケール（`ja-JP` のような BCP-47
  タグ）。
