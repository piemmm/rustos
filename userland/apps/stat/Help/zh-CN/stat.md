## NAME

stat — 报告文件或文件系统的状态

## SYNOPSIS

`stat [-Lft] [-c 格式 | --printf=格式] [--] 文件...`

## DESCRIPTION

按命令行顺序，为每个操作数报告一次读到的状态的各个字段。

**没有 `-L` 时，符号链接按它自身来描述。** 这正是本工具与 `ls` 并存的理
由。`%N` 显示链接以及它所存储的目标，`%F` 说 `symbolic link`，而大小和
时间戳都是链接自身的。`-L` 解析最后一个链接，描述它所指向的对象。

`-f` 切换到操作数所在的文件系统：卷的块数与索引节点数、它的块大小，以及
它的挂载所记录的类型。两种读法拥有**不同**的字段词汇，因此格式会针对
`-f` 选定的那一套来检查。

`-c`/`--format` 为每个操作数渲染一个格式串，并在其后加一个换行；
`--printf` 解释反斜杠转义，且不添加换行。两者的差别仅此而已。指令可带
printf 的标志与宽度（`%-10s`、`%06i`、`%.3n`），使报告能够对齐成列。
`-t` 是两种读法各自的单行简洁形式。

无法读取的操作数会报告到标准错误，其余操作数仍会被描述，随后命令以非零
状态退出。本系统无法提供的字段——它无权读取的挂载快照、用户目录中没有名
字的 uid——显示为 `?` 或 `UNKNOWN`，绝不显示貌似合理的替代值。

至少需要一个操作数。`--` 结束选项解析。

有四个字段命名了 TAIRiX 并不具备的概念；当格式用到其中之一时，它们会被
指名**拒绝**，而不是用编造的值来作答：`%G`，因为系统信息 API 发布的是
用户目录而没有与之对应的组目录，所以 `%g`（数字标识）才是诚实的字段；
文件词汇的 `%t` 和 `%T`，因为并不存在可以拥有主次类型的设备特殊文件；以
及文件系统词汇的 `%t`，因为卷没有数字的类型魔数——`%T` 命名它的挂载所记
录的类型。拒绝发生在解析格式之时，在触碰任何路径之前。

有两个字段报告 TAIRiX 的概念，而不是 Linux 的概念。卷由一个 16 字节的标
识而非设备号来标识，因此 `%d` 是该标识的十进制，`%D` 是它的十六进制；比
较两个文件的 `%d` 仍然精确地回答「它们是否在同一个卷上」。

## OPTIONS

- `-L, --dereference` — 描述符号链接所指向的对象，而不是链接本身。
- `-f, --file-system` — 描述容纳每个操作数的文件系统，而不是操作数。
- `-c, --format=FORMAT` — 为每个操作数渲染 `格式`，其后加一个换行。
- `--printf=FORMAT` — 与 `-c` 相同，但解释反斜杠转义，且不打印末尾换行。
- `-t, --terse` — 把各字段打印在以空格分隔的一行上。
- `-?, --help` — 显示本命令自己的简短帮助。

## EXAMPLES

- `stat notes.txt` — 一个文件的完整报告。
- `stat -c '%s %n' *` — 大小与名称，每个一行。
- `stat -L link` — 描述链接所指向的对象，而不是链接。
- `stat -f .` — 容纳工作目录的卷。

## EXIT STATUS

- `0` — 每个操作数都已被描述（或已写出简短帮助）。
- `1` — 至少有一个操作数无法读取，或输出失败。
- `2` — 未能理解命令行，或其格式指定了本系统无法提供的指令。

## ENVIRONMENT

- `LANG` — 简短帮助的首选区域设置（如 `fr-FR` 这样的 BCP-47 标签）。
