## NAME

stat — ファイルまたはファイルシステムの状態を報告する

## SYNOPSIS

`stat [-Lft] [-c 書式 | --printf=書式] [--] ファイル...`

## DESCRIPTION

オペランドごとに読んだ状態の各項目を、コマンド行の順に報告する。

**`-L` がなければシンボリックリンクはそれ自身として記述される。** `ls`
と並んでこの道具がある理由がそれである。`%N` はリンクとそれが格納する指
し先を示し、`%F` は `symbolic link` と言い、大きさと時刻はリンク自身の
ものである。`-L` は最後のリンクを解決し、それが指すものを記述する。

`-f` はオペランドが載っているファイルシステムに切り替える。ボリュームの
ブロック数とアイノード数、そのブロックサイズ、そしてマウントが記録して
いる種別である。二つの読み方は **別の** 項目語彙を持つので、書式は `-f`
が選んだ側に対して検査される。

`-c`/`--format` はオペランドごとに一つの書式文字列を出力し、続けて改行
を置く。`--printf` は逆斜線の並びを解釈し、改行を足さない。両者の違いは
それだけである。指示子は printf のフラグと幅（`%-10s`、`%06i`、`%.3n`）
を取るので、報告を桁で揃えられる。`-t` はどちらの読み方でも一行の簡潔な
形である。

読めなかったオペランドは標準エラーに報告され、残りのオペランドはそれで
も記述され、コマンドは非ゼロで終了する。この系が供給できない項目——読む
許可のないマウント一覧、利用者名簿に名前のない uid——は `?` または
`UNKNOWN` と出る。もっともらしい代用は決して出さない。

オペランドは少なくとも一つ必要である。`--` はオプション解析を終わらせる。

四つの項目は TAIRiX に存在しない概念を指しており、書式がそれを使った場
合は捏造した値で答えるのではなく、名前を挙げて **拒否** する。`%G` は、
システム情報 API が利用者名簿を公開し群の対応物を持たないため、`%g`（数
値の識別子）が正直な項目だからである。ファイル語彙の `%t` と `%T` は、
主番号や副番号を持つデバイス特殊ファイルが存在しないためである。ファイル
システム語彙の `%t` は、ボリュームに数値の種別マジックがないためであり、
`%T` がマウントの記録する種別を示す。拒否は書式の解析時、経路に触れる前
に起きる。

二つの項目は Linux の概念の代わりに TAIRiX の概念を報告する。ボリューム
はデバイス番号ではなく 16 バイトの識別子で識別されるので、`%d` はその識
別子の十進、`%D` は十六進である。二つのファイルの `%d` を比べれば、「同
じボリュームにあるか」にはこれまで通り正確に答えられる。

## OPTIONS

- `-L, --dereference` — リンク自身ではなく、シンボリックリンクが指すもの
  を記述する。
- `-f, --file-system` — オペランドではなく、それを保持するファイルシステ
  ムを記述する。
- `-c, --format=FORMAT` — オペランドごとに `書式` を出力し、続けて改行を
  置く。
- `--printf=FORMAT` — `-c` と同じだが、逆斜線の並びを解釈し、末尾の改行を
  出さない。
- `-t, --terse` — 項目を空白区切りの一行で出力する。
- `-?, --help` — このコマンド自身の短いヘルプを表示する。

## EXAMPLES

- `stat notes.txt` — 一つのファイルの完全な報告。
- `stat -c '%s %n' *` — 大きさと名前を一行ずつ。
- `stat -L link` — リンクではなく、リンクが指すものを記述する。
- `stat -f .` — 作業ディレクトリを保持するボリューム。

## EXIT STATUS

- `0` — 各オペランドを記述した（または短いヘルプを書き出した）。
- `1` — 少なくとも一つのオペランドが読めなかった、または出力が失敗した。
- `2` — コマンド行を解釈できなかった、またはその書式がこの系の供給できな
  い指示子を挙げた。

## ENVIRONMENT

- `LANG` — 短いヘルプの優先ロケール（`fr-FR` のような BCP-47 タグ）。
