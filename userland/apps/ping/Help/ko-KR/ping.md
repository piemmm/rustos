## NAME

ping — 네트워크 호스트에 ICMP 에코 요청 보내기

## SYNOPSIS

`ping [option...] 호스트`

## DESCRIPTION

호스트에 ICMP(IPv4) 또는 ICMPv6(IPv6) 에코 요청을 보내고 각 응답과
왕복 시간을 표시한 뒤 마지막에 통계 요약을 출력합니다.

요청은 사용자 공간 네트워크 스택에서 연 ICMP 에코 소켓을 통해 나가며,
`CAP_NET` 및 `CAP_NET_RAW`로 보호되고 감사됩니다. 에코 식별자는 스택이
소유하므로 소켓은 자신의 요청에 대한 응답만 받습니다.

대상은 리터럴 IPv4 또는 IPv6 주소이거나 호스트 이름입니다. 이름은 이
기기에 구성된 재귀 서버를 사용해 시스템 스텁 해석기가 해석합니다.
리터럴 주소는 질의가 전혀 필요 없으므로 해석기가 구성되지 않은 곳에서도
동작합니다. 요구한 주소 계열의 주소로 해석되지 않는 이름은 이유를 밝히며
실행을 끝냅니다.

각 요청은 기본적으로 고엔트로피 난수 데이터를 실어 보내며, 요청마다 새로
뽑습니다. 이는 의도된 것입니다. 트래픽을 압축하거나 중복 제거하는 링크는
그렇지 않으면 실제 용량과 무관한 처리량과 지연을 보고하게 됩니다. 돌아온
바이트는 보낸 바이트와 비교되므로 난수 페이로드는 패킷별 무결성 검사도
됩니다. 결정적인 페이로드가 필요하면 `-p`로 고정 패턴을 지정하십시오.

기본적으로 `ping`은 중단될 때까지 초당 하나의 요청을 보냅니다. `-c`는
개수를 제한합니다. 각 응답은 출처, 시퀀스 번호, 시간을 표시하며, 제한
시간 안에 응답이 없는 요청은 시간 초과 줄을 출력합니다. 요약은 보내고
받은 패킷, 손실률, 최소·평균·최대 왕복 시간을 보여줍니다. `-q`는 머리글과
요약만 표시합니다.

각 응답은 주소에 `PTR` 레코드가 있으면 상대를 `이름 (주소)`로 표시하며,
해석은 같은 스텁 리졸버로 실행당 한 번만 이뤄집니다. 이름이 없는 주소와
`-n`을 준 실행은 주소만 출력합니다. `-n`은 `PTR` 조회를 아예 보내지
않는다는 뜻이기도 합니다.

에코 소켓 인터페이스는 IP 수명(TTL)을 노출하지 않으므로 일부 `ping`
구현과 달리 응답 줄에는 `ttl=` 필드가 없습니다.

## OPTIONS

- `-c, --count` — 이만큼의 요청을 보낸 뒤 중지.
- `-i, --interval` — 요청 사이의 초(소수, 예: `0.5`).
- `-s, --size` — 페이로드 바이트 수.
- `-p, --pattern` — 페이로드 내용: `random`(기본값, 고엔트로피) 또는
  짝수 길이의 16진 숫자열을 반복 바이트 패턴으로. 예: `-p ff00`.
- `-W, --timeout` — 각 응답을 기다리는 초.
- `-w, --deadline` — 전체 실행의 기한(초).
- `-4, --ipv4` — IPv4 대상 요구.
- `-6, --ipv6` — IPv6 대상 요구.
- `-n, --numeric` — 숫자 출력: 상대를 역방향 해석하지 않으므로 `PTR`
  조회를 보내지 않고 응답 줄에는 주소만 나타난다.
- `-q, --quiet` — 조용히: 머리글과 최종 요약만.
- `-?, --help` — 이 명령의 짧은 도움말 표시.

## EXAMPLES

- `ping 10.0.2.2` — 중단될 때까지 IPv4 호스트에 핑.
- `ping -c 4 fe80::1` — IPv6 호스트에 네 번 요청 전송.
- `ping -c 10 -i 0.2 10.0.0.1` — 열 번, 200 ms마다 한 번.
- `ping -q -c 100 10.0.0.1` — 조용한 실행, 요약만.

## EXIT STATUS

- `0` — 적어도 하나의 응답을 받음(또는 짧은 도움말을 출력함).
- `1` — 어떤 요청도 응답을 받지 못함.
- `2` — 명령줄을 이해할 수 없거나, 대상이 해석되지 않거나, 소켓을 열 수 없음.

## ENVIRONMENT

- `LANG` — 짧은 도움말의 선호 로캘(`fr-FR` 같은 BCP-47 태그).
