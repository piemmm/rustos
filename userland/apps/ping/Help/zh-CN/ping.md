## NAME

ping — 向网络主机发送 ICMP 回显请求

## SYNOPSIS

`ping [option...] 主机`

## DESCRIPTION

向主机发送 ICMP（IPv4）或 ICMPv6（IPv6）回显请求，并显示每个回复及其
往返时间，最后给出统计摘要。

请求通过在用户空间网络栈中打开的 ICMP 回显套接字发送，受 `CAP_NET` 和
`CAP_NET_RAW` 保护并记入审计。回显标识符由网络栈持有，因此一个套接字
只会收到对自身请求的回复。

目标可以是字面的 IPv4 或 IPv6 地址，也可以是主机名。名称由系统存根解析
器解析，使用本机配置的递归服务器；字面地址无需任何查询，因此即使没有
配置解析器也能使用。若某个名称解析不出所需地址族的任何地址，运行随即
结束并说明原因。

每个请求默认携带高熵随机数据，且每个请求重新抽取。这是有意的：压缩或
去重流量的链路否则会报出与其真实容量毫无关系的吞吐量和时延。回传的字节
会与发出的字节比对，因此随机负载同时也是逐包的完整性校验。若需要确定性
负载，用 `-p` 指定固定模式。

默认情况下 `ping` 每秒发送一个请求，直到被中断；`-c` 限制数量。每个
回复给出来源、序号和时间；在超时内未收到回复的请求会打印一行超时。
摘要给出已发送和已接收的数据包、丢包百分比，以及最小、平均和最大往返
时间。`-q` 只显示表头和摘要。

当地址存在 `PTR` 记录时，每条回复以 `名字 (地址)` 命名对端；解析由同一个
存根解析器在每次运行中只做一次。没有名字的地址，以及带 `-n` 的每次运行，
都只打印裸地址。`-n` 还意味着根本不会发出 `PTR` 查询。

回显套接字接口不暴露 IP 生存时间，因此与某些 `ping` 实现不同，回复行
不带 `ttl=` 字段。

## OPTIONS

- `-c, --count` — 发送这么多请求后停止。
- `-i, --interval` — 请求之间的秒数（小数，如 `0.5`）。
- `-s, --size` — 负载字节数。
- `-p, --pattern` — 负载内容：`random`（默认，高熵）或偶数长度的十六进制
  数字串，作为重复的字节模式，例如 `-p ff00`。
- `-W, --timeout` — 每个回复的等待秒数。
- `-w, --deadline` — 整个运行的截止秒数。
- `-4, --ipv4` — 要求 IPv4 目标。
- `-6, --ipv6` — 要求 IPv6 目标。
- `-n, --numeric` — 数字输出：不对对端做反向解析，因此不发出任何 `PTR`
  查询，回复行只带裸地址。
- `-q, --quiet` — 安静：只有表头和最终摘要。
- `-?, --help` — 显示此命令自带的简短帮助。

## EXAMPLES

- `ping 10.0.2.2` — 持续 ping 一个 IPv4 主机直到中断。
- `ping -c 4 fe80::1` — 向 IPv6 主机发送四个请求。
- `ping -c 10 -i 0.2 10.0.0.1` — 十个请求，每 200 毫秒一个。
- `ping -q -c 100 10.0.0.1` — 安静运行，只有摘要。

## EXIT STATUS

- `0` — 至少收到一个回复（或已写出简短帮助）。
- `1` — 所有请求都没有回复。
- `2` — 无法理解命令行、目标未能解析，或无法打开套接字。

## ENVIRONMENT

- `LANG` — 简短帮助的首选区域设置（BCP-47 标签，如 `fr-FR`）。
