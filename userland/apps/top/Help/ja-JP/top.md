## NAME

top — プロセス一覧を生で見張る

## SYNOPSIS

`top [-d secs.tenths] [-h | -?]`

## DESCRIPTION

GNU `top` の精神で、システム情報 API を通したプロセス一覧の生の全画面
ビューを表示します。呼び出し元自身のプロセスから始まります。システム全体
のビューは、`CAP_SYSINFO_GLOBAL` を持つ呼び出し元にだけサービスが許しま
す。

表示は遅延間隔ごとに自動更新され（`-d` で変えない限り 3.0 秒）、`r` で即
座に更新されます。

ビューアはオペランドを取りません。セッション内で押すキーで操作します。

- `q` — 終了する。
- `a` — 自分のプロセスとシステム全体のビューを切り替える。サービスがシス
  テム全体のビューを拒否したら（`CAP_SYSINFO_GLOBAL` が必要）、ビューア
  は自分のプロセスに留まり、状態行が理由を告げる。セッションは走り続け
  る。
- `r` — 一覧を更新する。
- 上/下、PageUp/PageDown、Home/End — 選択を動かす。
- `h`、`?` — セッション内のキー一覧の重ね表示を切り替える。

一覧の前に四行の要約が並びます。稼働時間・ログイン中ユーザー数・1/5/15
分の負荷平均、状態別のタスク数、`%Cpu(s)` の利用率内訳、そして MiB 単位
のメモリの数字です。メモリの行には `CAP_SYSINFO_KERNEL` が要ります。持た
ない呼び出し元には拒否が明記され、セッションは続きます。

`%Cpu(s)` の行は、直前の間隔にすべての CPU が合わせて忙しく（タスクを実
行して）過ごした割合と、待機していた割合を示します。RustOS は忙と閑の時
間だけを計上するため、GNU `top` が忙の割合を user/system/nice/iowait に
分けるところを、この行は意図的に二つの実数値だけを示します。

行は `%CPU` 順、最大の消費者から並び、次を運びます。

- `PID` — 数値のプロセス id。
- `USER` — 所有アカウントのユーザー名。システムのアカウント台帳から解決
  され、解決できないときは数値の uid が代わりに立つ。
- `SIZE` — プロセスのアドレス空間にマップされたメモリ（イメージ・スタッ
  ク・ヒープを問わず）。
- `S` — 状態の文字。`R` 実行中（緑）、`r` 実行可能で CPU 待ち（シアン）、
  `S` 眠り、`T` 停止（黄）、`Z` ゾンビ（マゼンタ）。色はカラー端末での
  み。文字自体が常に状態を運ぶ。
- `%CPU` — 前回の更新からの間隔での CPU の割合。
- `WCPU` — 更新をまたいで重み付け（指数平滑）した CPU の割合。瞬時の列よ
  り安定している。
- `TIME+` — 累積 CPU 時間。`分:秒.百分の一秒` の形。
- `COMMAND` — プロセス名。

## OPTIONS

- `-d, --delay <seconds>` — 自動更新の間隔。秒単位で、任意の小数を付けら
  れる（小数第一位、十分の一秒だけが保持される）。`top -d 1.5` は 1.5 秒
  ごとに更新する。既定は 3.0。GNU `top` はゼロの遅延を受け付けて可能な限
  り速く更新するが、RustOS は決してビジーループしないので、ゼロは最小の
  0.1 秒に丸められる。
- `-h, -?` — このコマンド自身の短いヘルプを表示して終了する。実行中の
  セッション内では、同じキーはキー一覧の重ね表示を切り替える。

## EXIT STATUS

- `0` — セッションが `q` で終わった、または短いヘルプを表示した。
- `1` — サービスまたは端末が失敗した。理由は標準エラーに印字される。
- `2` — コマンド行を解釈できなかった。

## ENVIRONMENT

- `LANG` — 短いヘルプの優先ロケール（`ja-JP` のような BCP-47 タグ）。
