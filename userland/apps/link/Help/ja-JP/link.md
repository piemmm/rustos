## NAME

link — ファイルに二つめの名前を与える

## SYNOPSIS

`link [--] 既存 新規`

## DESCRIPTION

ハードリンクを一つ作る。`新規` が、`既存` がすでに指している同じノード
の二つめの名前になる。以後どちらの名前も同じファイルに達する。一方から
の書き込みは他方からも見える。コピーではなく一つのファイルだからであ
る。ファイルの記憶領域は、最後の名前が削除されるまで残る。

オプションは意図的に一つもない。`-f`、`-i`、`-v`、`-s`、`-L`/`-P`、そ
して `-t`/`-T` の宛先形式を持つのは `ln` である。分けておくことの意味
は、ハードリンクを一つ作るだけでそれ以上は何もしない必要のあるスクリプ
トが、名前を置き換えることもリンクをたどることも代わりにシンボリックリ
ンクを作ることもできない道具を得る、という点にある。

どちらの名前もたどられない。`既存` は **書かれたとおりの** ノードなの
で、そこに仕込まれたシンボリックリンクが新しい名前を指し先へ付け替える
ことはできない（たどる姿勢が必要なら `ln -L`）。`新規` は作られる側の
名前なので、すでに使われていれば拒否され、置き換えられることはない。

拒否はそれぞれ別のことを述べる。

- 新しい名前がすでに存在する。作成が名前を置き換えることはない。
- `既存` が **ディレクトリ** である。ディレクトリはどこでもちょうど一
  つの名前を持つので、二つめを与えられる主体は存在しない。
- 二つの名前が **別のボリューム** にある。ノードの二つめの名前は、その
  ノードを格納するボリューム上にある必要がある。
- その形式のノードごとの名前数があふれる。
- ファイルシステムが **ノードごとに一つの名前** しか格納しない。これは
  その形式の恒久的な性質であって一時的な失敗ではない。そこではシンボリ
  ックリンクに `ln -s` を使う。

オペランドはちょうど二つ必要である。それ以外は使用法の誤りで、リンクは
作られない。`--` はオプション解析を終わらせる。

## OPTIONS

- `-?, --help` — このコマンド自身の短いヘルプを表示する。

## EXAMPLES

- `link report.txt report-backup.txt` — 一つのファイルに二つめの名前。
- `link -- -奇妙な名前 二つめ` — ハイフンで始まる名前をリンクする。

## EXIT STATUS

- `0` — リンクを作成した（または短いヘルプを書き出した）。
- `1` — ファイルシステムがリンクを拒否した、または出力が失敗した。理由
  は標準エラーに表示される。
- `2` — コマンド行を解釈できなかった。

## ENVIRONMENT

- `LANG` — 短いヘルプの優先ロケール（`fr-FR` のような BCP-47 タグ）。
