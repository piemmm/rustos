## NAME

link — 给文件第二个名称

## SYNOPSIS

`link [--] 已有 新建`

## DESCRIPTION

创建一个硬链接：`新建` 成为 `已有` 已命名的那个节点的第二个名称。此后
两个名称到达同一个文件——通过其中一个写入，从另一个也能看到，因为这是
一个文件而不是一份副本——并且该文件的存储会一直保留，直到它的最后一个
名称被删除。

这里有意不提供任何选项。`ln` 才是带 `-f`、`-i`、`-v`、`-s`、`-L`/`-P`
以及 `-t`/`-T` 目标形式的工具；把它们分开的意思是：只需创建一个硬链接
而不做其他事的脚本，会得到一个既不能替换名称、也不能跟随链接、更不能
改为创建符号链接的工具。

两个名称都不会被跟随。`已有` 就是**所写的**那个节点，因此放在那里的符
号链接无法把新名称重定向到它所指之处（需要跟随时用 `ln -L`）。`新建`
是正在创建的名称：已被占用时会被拒绝，绝不替换。

各种拒绝各说明不同的事：

- 新名称已存在——创建绝不替换名称；
- `已有` 是**目录**——目录在任何地方都恰好只有一个名称，因此任何主体
  都不能给它第二个；
- 两个名称位于**不同卷**上——节点的第二个名称必须位于存储它的卷上；
- 该格式的每节点名称计数会溢出；
- 文件系统**每个节点只存一个名称**——这是该格式的固有属性，而不是一
  时的故障。在那里请用 `ln -s` 创建符号链接。

必须恰好给出两个操作数；其他情况都是用法错误，并且不会创建链接。`--`
结束选项解析。

## OPTIONS

- `-?, --help` — 显示本命令自己的简短帮助。

## EXAMPLES

- `link report.txt report-backup.txt` — 给一个文件第二个名称。
- `link -- -奇怪的名称 第二个` — 链接以短横线开头的名称。

## EXIT STATUS

- `0` — 链接已创建（或已写出简短帮助）。
- `1` — 文件系统拒绝了该链接，或输出失败；原因打印到标准错误。
- `2` — 未能理解命令行。

## ENVIRONMENT

- `LANG` — 简短帮助的首选区域设置（如 `fr-FR` 这样的 BCP-47 标签）。
