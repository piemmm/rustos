## NAME

stress — マシンの CPU・メモリ・ディスク・キャッシュに意図的な負荷をかける

## SYNOPSIS

`stress [--cpu N] [--io N] [--vm N] [--vm-bytes B] [--hdd N] [--hdd-bytes B] [--cache N] [--all N] [--overcommit P] [--timeout T] [--temp-path DIR] [--monitor] [--quiet] [--background]`

## DESCRIPTION

確立されたツール `stress`/`stress-ng` の流儀で、マシンに意図的な負荷を
かけるワーカープロセスを起動します。CPU ループ（`--cpu`）、メモリの
確保とタッチを行うワーカー（`--vm`）、小さなバッファの書き込みと同期
（`--io`）、大きな順次ディスク書き込み（`--hdd`）、キャッシュを撹拌する
再読ワーカー（`--cache`、TAIRiX 独自の追加）です。各ワーカーはスワップ
可能な独立プロセスであり、制御プロセスは自らのメモリを固定して
（`mem_pin`、`CAP_MEM_PIN` が必要）自ら生み出す圧力の下でも応答性を
保ち、`Ctrl-C`/`Terminate` を観測するため、完了・タイムアウト・
シグナルのいずれで終わってもワーカーを停止・回収し、作業ファイルを
すべて削除します。

メモリとディスクの目標量はマシン自体から算出されます。
`--vm-bytes`/`--hdd-bytes` が明示されない限り、vm ワーカーは検出された
RAM の半分を、hdd ワーカーは作業ボリュームの空き容量の半分を分け合い
ます。`--overcommit P` は検出済みの目標をリソースの `P` パーセントに
再設定します。100 を超えるとワーカーは圧力域に踏み込み、そこで生じる
型付きの拒否（満杯のボリューム、リソース上限）は想定内の結果として
数えられ報告されます — 再試行もクラッシュもしません。マシンに負荷を
かけるのに呼び出し側自身のリソース制限を超える権限は不要です — 制限
こそが防御であり、`stress` はそれを尊重します。

ディスクに触れるワーカーは作業ディレクトリの下にのみ書き込みます —
`--temp-path` が別を指定しない限り、アプリ用ユーザーキャッシュ
ディレクトリ（`$HOME/Library/stress`）です — そして作業ファイルは
シグナル経路を含むすべての終了時に削除されます。

実行終了時に要約が出力され（`--quiet` で抑制）、機械可読の `summary`
レコードが助言用の標準情報ストリーム（fd 3）に発行されます。

## OPTIONS

- `--cpu N`, `--io N`, `--vm N`, `--hdd N` — 指定した種類のワーカーを
  `N` 個起動します（GNU `stress` と同じ意味）。
- `--cache N` — キャッシュ撹拌ワーカーを `N` 個起動します（TAIRiX
  独自：冷たいディレクトリ走査と再読の繰り返しがカーネルの回収可能
  キャッシュ台帳を動かします）。
- `--all N` — 各種類のワーカーを `N` 個ずつ。
- `--vm-bytes B`, `--hdd-bytes B` — 各ワーカーのバイト目標。GNU の
  接尾辞（`k`、`m`、`g`、`t`。例 `256M`）が使えます。既定値は検出
  された RAM／空き容量から算出されます。
- `--overcommit P` — 検出済みの vm/hdd 目標をリソースの `P`
  パーセントに設定します。100 を超えても構いません（その場合の拒否は
  想定内の結果です）。
- `--timeout T` — `T` の経過後に停止します（接尾辞 `s`/`m`/`h`。例
  `5m`）。既定値はなく、指定しなければシグナルが終わらせるまで実行が
  続きます。
- `--temp-path DIR` — ディスクに触れるワーカーの作業ディレクトリ。
- `--monitor` — 実行の間 `sysmon` を前面で動かします。モニターが
  終了したときに実行が報告されます。`--background` とは両立しません。
- `-q, --quiet` — stdout の要約と進捗行を抑制します（エラーは
  引き続き stderr に届きます）。
- `--background` — 切り離された制御プロセスの PID を出力して
  プロンプトを返します（`--quiet` を含意）。シェルの `&` ジョブ形式も
  使えます。このフラグはスクリプト向けです。
- `-h, -?, --help` — このコマンド自身の短いヘルプを表示して終了。
- `--version` — ツール名とバージョンを出力して終了。

## EXIT STATUS

- `0` — 実行が完了しました（ワーカーの型付き拒否は想定内の結果で、
  失敗にはなりません）。
- `1` — ワーカーが実際に失敗したか、実行を準備できませんでした。
- `2` — コマンド行を解釈できませんでした。
- `130` / `143` — `Ctrl-C` / `Terminate` が実行を終わらせました。
  ワーカーの解体と作業ファイルの削除は完了しています。

## ENVIRONMENT

- `HOME` — 既定の作業ディレクトリ（`$HOME/Library/stress`）を
  決めます。
- `LANG` — 短いヘルプの優先ロケール（`ja-JP` のような BCP-47
  タグ）。
