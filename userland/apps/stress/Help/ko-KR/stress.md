## NAME

stress — 머신의 CPU·메모리·디스크·캐시에 의도적인 부하를 건다

## SYNOPSIS

`stress [--cpu N] [--io N] [--vm N] [--vm-bytes B] [--hdd N] [--hdd-bytes B] [--cache N] [--all N] [--overcommit P] [--timeout T] [--temp-path DIR] [--monitor] [--quiet] [--background]`

## DESCRIPTION

확립된 도구 `stress`/`stress-ng`의 방식대로 머신에 의도적으로 부하를
거는 워커 프로세스들을 실행합니다: CPU 루프(`--cpu`), 메모리
할당-후-접촉 워커(`--vm`), 작은 버퍼 쓰기/동기화(`--io`), 큰 순차
디스크 쓰기(`--hdd`), 캐시를 휘젓는 재독 워커(`--cache`, RustOS
전용 추가). 각 워커는 스왑 가능한 독립 프로세스이며, 제어 프로세스는
자기 메모리를 고정하여(`mem_pin`, `CAP_MEM_PIN` 필요) 스스로 만드는
압력 아래에서도 응답성을 유지하고 `Ctrl-C`/`Terminate`를 관찰하므로,
완료·시간 초과·시그널 등 어떤 종료든 워커를 멈추고 수거하며 모든
작업 파일을 제거합니다.

메모리와 디스크 목표량은 머신 자체에서 산정됩니다.
`--vm-bytes`/`--hdd-bytes`가 명시되지 않으면 vm 워커들은 발견된 RAM의
절반을, hdd 워커들은 작업 볼륨 여유 공간의 절반을 나눠 가집니다.
`--overcommit P`는 발견된 목표를 자원의 `P` 퍼센트로 재조정합니다.
100을 넘으면 워커들이 압력 구간으로 밀고 들어가며, 그때 생기는 형식
있는 거부(가득 찬 볼륨, 자원 한도)는 예상된 결과로 집계·보고됩니다 —
재시도도, 충돌도 없습니다. 머신에 부하를 거는 데 호출자 자신의 자원
한도를 넘는 권한은 필요 없습니다 — 한도가 곧 방어이며, `stress`는
그것을 존중합니다.

디스크를 만지는 워커는 작업 디렉터리 아래에만 씁니다 — `--temp-path`
가 다른 곳을 지정하지 않는 한 앱 전용 사용자 캐시 디렉터리
(`$HOME/Library/stress`)입니다 — 그리고 모든 작업 파일은 시그널
경로를 포함한 모든 종료 시 제거됩니다.

실행이 끝나면 요약이 출력되고(`--quiet`로 억제), 기계가 읽을 수 있는
`summary` 레코드가 자문용 표준 정보 스트림(fd 3)으로 발행됩니다.

## OPTIONS

- `--cpu N`, `--io N`, `--vm N`, `--hdd N` — 지정한 종류의 워커를
  `N`개 실행합니다(GNU `stress`와 같은 의미).
- `--cache N` — 캐시 휘젓기 워커를 `N`개 실행합니다(RustOS 전용:
  차가운 디렉터리 순회와 재독의 반복이 커널의 회수 가능 캐시 장부를
  움직입니다).
- `--all N` — 모든 종류의 워커를 `N`개씩.
- `--vm-bytes B`, `--hdd-bytes B` — 각 워커의 바이트 목표. GNU
  접미사(`k`, `m`, `g`, `t`; 예 `256M`)를 씁니다. 기본값은 발견된
  RAM/여유 공간에서 산정됩니다.
- `--overcommit P` — 발견된 vm/hdd 목표를 자원의 `P` 퍼센트로
  조정합니다. 100을 초과할 수 있습니다(그때의 거부는 예상된
  결과입니다).
- `--timeout T` — `T` 뒤에 멈춥니다(접미사 `s`/`m`/`h`; 예 `5m`).
  기본값이 없어, 지정하지 않으면 시그널이 끝낼 때까지 계속됩니다.
- `--temp-path DIR` — 디스크를 만지는 워커의 작업 디렉터리.
- `--monitor` — 실행 동안 `sysmon`을 전면에서 돌립니다. 모니터가
  종료될 때 실행이 보고됩니다. `--background`와는 모순됩니다.
- `-q, --quiet` — stdout의 요약과 진행 줄을 억제합니다(오류는
  여전히 stderr에 도달합니다).
- `--background` — 분리된 제어 프로세스의 PID를 출력하고 프롬프트를
  돌려줍니다(`--quiet` 포함). 셸의 `&` 잡 형식도 동작하며, 이
  플래그는 스크립트용입니다.
- `-h, -?, --help` — 이 명령 자체의 짧은 도움말을 보여주고 종료.
- `--version` — 도구 이름과 버전을 출력하고 종료.

## EXIT STATUS

- `0` — 실행이 완료되었습니다(워커의 형식 있는 거부는 예상된
  결과이며 실패로 만들지 않습니다).
- `1` — 워커가 실제로 실패했거나, 실행을 준비할 수 없었습니다.
- `2` — 명령줄을 이해할 수 없었습니다.
- `130` / `143` — `Ctrl-C` / `Terminate`가 실행을 끝냈습니다. 워커
  해체와 작업 파일 제거는 완료된 뒤입니다.

## ENVIRONMENT

- `HOME` — 기본 작업 디렉터리(`$HOME/Library/stress`)를 정합니다.
- `LANG` — 짧은 도움말의 선호 로캘(`ko-KR` 같은 BCP-47 태그).
