## NAME

lspci — 발견된 PCI/PCIe 장치 나열

## SYNOPSIS

`lspci [-n | -nn] [-v] [-t] [-d [<vendor>]:[<device>]] [-s <node>]`

## DESCRIPTION

발견된 PCI/PCIe 기능마다 한 줄씩, 해당 기능의 하드웨어 트리 노드
번호, 클래스, 제조사와 장치 이름을 표시합니다. 목록은 하드웨어
트리— 시스템의 유일한 장치 목록 —이며 시스템 정보 API를 통해
읽히고 `CAP_SYSINFO_HW` 능력이 필요합니다. 거부되면 표준 오류에
이유가 보고되며 그 대신 아무것도 나열되지 않습니다.

이름은 이 명령이 자체 번들에 담아 배포하는, 검증된 공개 PCI ID
데이터베이스 스냅숏에서 옵니다. 데이터베이스에 없는 식별자는 숫자
형태(`Vendor 8086`, `Device 2922`, `Class 0106`)로 표시되며 결코
지어내지 않고, 그러한 장치의 수는 표준 정보 스트림(fd 3)에
기록됩니다. 동봉된 테이블이 없거나 검증에 실패하면 목록은 숫자
ID로 낮춰지고 이유가 표준 오류에 보고됩니다 — 목록 자체는 계속
표시됩니다.

RustOS는 PCI `bus:device.function` 주소를 기록하지 않습니다. 기능의
안정적인 주소는 하드웨어 트리 노드 번호이며 `#<node>`로 표시되고,
`-s`가 그 번호를 선택합니다(리눅스 `lspci`와의 의도적이고 문서화된
차이). `-k`(커널 드라이버) 보기는 아직 제공되지 않습니다. 시스템이
드라이버 결합 기록을 공개하지 않으므로 `lspci`는 시스템이 실제로
기록한 것만 보고합니다.

## OPTIONS

- `-n` — 숫자 ID만: 클래스 코드와 16진수 `vendor:device`.
- `-nn` — 이름 뒤에 숫자 ID를 대괄호로 표시.
- `-v` — 각 기능 뒤에 그 노드가 선언한 자원(MMIO 창, IRQ 선, I/O
  포트, DMA 제약)을 나열 — 트리에 기록된 능력 부여 요청이며 실시간
  상태가 아님.
- `-t` — 기능을 버스 부모 아래 트리로 표시.
- `-d [<vendor>]:[<device>]` — 주어진 제조사/장치 ID(16진수)와
  일치하는 기능만 나열; 생략한 절반은 무엇이든 일치.
- `-s <node>` — 주어진 하드웨어 트리 노드 번호(10진수)를 가진
  기능만 나열.
- `-?, --help` — 이 명령의 짧은 도움말 표시.

## EXAMPLES

- `lspci` — 발견된 모든 PCI 기능을 이름과 함께.
- `lspci -nn` — 같은 내용에 숫자 ID를 함께 표시.
- `lspci -v -s 7` — 노드 7의 줄과 선언된 자원.
- `lspci -d 1af4:` — 제조사 `1af4`(virtio)의 모든 기능.
- `lspci -t` — 버스 토폴로지 아래의 기능들.

## EXIT STATUS

- `0` — 목록(또는 짧은 도움말)을 출력함.
- `1` — 하드웨어 트리 질의가 거부되거나 실패했거나 출력을 쓸 수
  없었음.
- `2` — 명령줄을 이해하지 못함.

## ENVIRONMENT

- `LANG` — 짧은 도움말에 사용할 선호 로캘(`ko-KR` 같은 BCP-47
  태그).
