## NAME

applib — デスクトップのプログラムライブラリを管理する

## SYNOPSIS

`applib [list [--category <folder>]]`

`applib add <bundle> [--category <folder>] [--name <name>] [--icon <asset>] [--user]`

`applib remove <id|bundle> [--user]`

`applib hide <id> [--user]`

`applib show <id> [--user]`

`applib rescan [--user]`

## DESCRIPTION

デスクトップのランチャーが表示する、フォルダ形式で整理された起動可能なア
プリケーションのカタログであるプログラムライブラリを管理します。ライ
ブラリはボリューム上のデータであり、コンパイル時に組み込まれたリスト
ではありません。すべてのユーザーが読み取る
`/System/Settings/ProgramLibrary/library.conf` にあるマシン全体のストアと、
ユーザー自身の `Settings/` 内の同じパスにあるオプションのユーザーごとの
オーバーレイで構成されます。ランチャーが表示するのは、この2つを組み合わ
せて解決した結果です。ユーザー自身の構成と調整は、マシン全体の構成より
も優先されます。

サブコマンドなし（または `list`）の場合、解決されたライブラリがフォルダ
ごとに1行に1エントリずつ出力されます。表示内容は、識別子、表示名、バン
ドルパスであり、これはランチャーの表示とまったく同じです。フォルダは、
`Accessories`、`Graphics`、`Internet`、`Multimedia`、`Office`、
`Programming`、`Games`、`SystemTools`、`Utilities`、`Other` の固定された
セットであり、自由な形式のフォルダは存在しません。

`applib add` はアプリケーションバンドルを登録します。その識別子、表示名、
フォルダ、およびアイコンは、バンドル自身の署名済み `AppInfo` マニフェス
トから取得されます。`--category`、`--name`、および `--icon` を指定すると、
マニフェストの設定が上書きされます。マニフェストでライブラリフォルダが
宣言されていないバンドルには、明示的な `--category` が必要です。このツー
ルが推測することはありません。`applib remove` は、識別子または登録時の
バンドルパスで指定されたレコードを削除します。

`applib hide` は、レコードを削除せずに、解決されたライブラリからエントリ
を抑制します。識別子は確保されたままになるため、後で `rescan` を実行して
も復活することはありません。`applib show` を実行すると再表示されます。
非表示化は表示上の問題であり、権限に関するものではありません。バンドル
の起動は、カタログの設定にかかわらず、常にローダーの署名および
ケイパビリティ（capability）チェックによって制御されます。

`applib rescan` は、アプリケーションストア（`/System/Commands`、
`/System/Applications` および `/Apps`、または `--user` 指定時は呼び出し
元自身の `<home>/Commands` と `<home>/Applications`）をスキャンし、各
バンドルのマニフェストを読み取り、リストへの掲載を要求していて、かつま
だカタログに登録されていないすべてのアプリケーションを登録します。既存
のレコード（キュレーターによる名前の変更や抑制を含む）が妨げられること
はなく、読み取り不能または不正な形式のマニフェストを持つバンドルはスキッ
プされ、カウントされます。これが中止の理由になることはありません。これ
により、手動で管理されたリストを一切使用せずに、実際にインストールされ
ているバンドルから新しいシステムのライブラリが自動的に構成されます。

デフォルトでは、ツールはマシン全体のストアを編集します。これを変更でき
るのは、`/System/Settings` の書き込みポリシーによって許可されたプリンシ
パルのみです。通常のユーザーアカウントはこれを読み取りますが、
`--user` による独自のオーバーレイを通じて個人設定を行います。書き込みが
拒否された場合はその理由が表示され、変更は行われません。

成功した場合、ツールは標準出力には何も出力しません。変更の結果は、構造
化されたアドバイザリレコードとして標準情報ストリーム (fd 3) に出力され
ます。これは、スクリプトで `3>records.jsonl` を使用して取得することも、
無視することも可能です。

## OPTIONS

- `--category <folder>` — `list` の場合、そのフォルダのみを表示します。
  `add` の場合、エントリをそのフォルダに分類します（マニフェストの宣
  言を上書きします）。
- `--name <name>` — `add` の場合、マニフェストの名称の代わりに表示する
  表示名を指定します。
- `--icon <asset>` — `add` の場合、マニフェストのアイコンの代わりに指定
  するアイコンアセット（バンドルの `Resources/` 内のファイル名）を指定
  します。
- `--user` — 変更をマシン全体のストアではなく、呼び出し元独自のオー
  バーレイに適用します（または `rescan` の場合に呼び出し元自身の
  `<home>/Commands` と `<home>/Applications` をスキャンします）。
- `-h, -?` — このコマンドの短いヘルプを表示します。

## EXAMPLES

- `applib` — 解決されたライブラリをフォルダごとに表示します。
- `applib list --category Games` — 1つのフォルダのみを表示します。
- `applib add /Apps/chess.app` — マニフェストの要求に従ってバンドルを
  登録します。
- `applib add /Apps/tool.app --category Utilities --name "Disk Tool"` —
  掲載宣言のないバンドルを、明示的なフォルダの下に登録します。
- `applib remove os.tairix.chess` — 識別子でエントリを削除します。
- `applib hide os.tairix.chess --user` — 自分のライブラリからのみ非表
  示にします。
- `applib rescan` — インストールおよびリスト掲載されているが、まだマ
  シンのカタログにないすべてのバンドルを登録します。

## EXIT STATUS

- `0` — リスト表示、変更、再スキャン、または短いヘルプが完了しました。
- `1` — ストア、バンドル、または出力の失敗（例えば、呼び出し元がマシ
  ン全体のカタログを変更できない場合など）。理由は診断ストリームに表
  示されます。
- `2` — コマンドラインが解釈できない、フォルダまたはエントリが不明、
  またはバンドルを指定通りに登録できません。

## ENVIRONMENT

- `LANG` — 短いヘルプの優先ロケール（`fr-FR` などの BCP-47 タグ）。
- `HOME` — 呼び出し元のホームディレクトリ。ユーザーごとのオーバーレイ
  および `--user` 再スキャンのルート `<home>/Commands` と
  `<home>/Applications` を指定します。
