## NAME

applib — 데스크톱 프로그램 라이브러리 관리

## SYNOPSIS

`applib [list [--category <folder>]]`

`applib add <bundle> [--category <folder>] [--name <name>] [--icon <asset>] [--user]`

`applib remove <id|bundle> [--user]`

`applib hide <id> [--user]`

`applib show <id> [--user]`

`applib rescan [--user]`

## DESCRIPTION

데스크톱 런처가 표시하는 폴더별로 정리된 실행 가능한 애플리케이션 카탈로그인
프로그램 라이브러리를 관리합니다. 라이브러리는 볼륨 상의 데이터이며,
컴파일 시 포함된 목록이 아닙니다. 모든 계정이 읽는 시스템 전체 저장소인
`/System/Settings/ProgramLibrary/library.conf`와 사용자 자신의 `Settings/`
내 동일한 경로에 있는 선택적인 사용자별 오버레이로 구성됩니다.
런처가 표시하는 내용은 이 두 가지를 결합하여 해석한 결과입니다.
사용자 고유의 항목 및 조정 사항이 시스템 전체 설정보다 우선합니다.

하위 명령 없이(또는 `list` 사용 시) 해석된 라이브러리가 폴더별로 한 줄에
하나의 항목(식별자, 표시 이름, 번들 경로)씩 출력됩니다. 이는 런처에
표시되는 내용과 정확히 일치합니다. 폴더는 `Accessories`, `Graphics`,
`Internet`, `Multimedia`, `Office`, `Programming`, `Games`, `SystemTools`,
`Utilities`, `Other`의 고정된 세트이며, 자유 형식의 폴더는 존재하지 않습니다.

`applib add`는 애플리케이션 번들을 등록합니다. 식별자, 표시 이름, 폴더,
아이콘은 번들 자체의 서명된 `AppInfo` 매니페스트에서 가져옵니다.
`--category`, `--name`, `--icon` 옵션은 매니페스트 설정을 재정의합니다.
매니페스트에 라이브러리 폴더가 선언되지 않은 번들은 명시적인 `--category`가
필요하며, 도구는 이를 임의로 추측하지 않습니다. `applib remove`는 식별자
또는 등록 시 사용된 번들 경로로 지정된 레코드를 삭제합니다.

`applib hide`는 레코드를 삭제하지 않고 해석된 라이브러리에서 항목을
억제합니다. 식별자는 점유된 상태로 유지되므로 나중에 `rescan`을 실행해도
복구되지 않습니다. `applib show`는 이를 다시 표시합니다.
숨기기는 표시 방식의 문제일 뿐 권한과는 무관합니다. 번들 실행은 카탈로그와
관계없이 항상 로더의 서명 및 기능(capability) 체크에 의해 제어됩니다.

`applib rescan`은 애플리케이션 저장소(`/System/Apps` 및 `/Apps`,
또는 `--user` 지정 시 호출자 자신의 `<home>/Apps`)를 검색하고, 각 번들의
매니페스트를 읽어 목록 게시를 요청하고 아직 카탈로그에 등록되지 않은 모든
애플리케이션을 등록합니다. 큐레이터의 이름 변경 및 억제 사항을 포함한 기존
레코드는 절대 건드리지 않으며, 읽을 수 없거나 형식이 잘못된 매니페스트가
포함된 번들은 건너뛰고 횟수만 기록합니다. 이것이 중단 사유가 되지는 않습니다.
이러한 방식으로 수동 관리 목록 없이 실제로 설치된 번들을 통해 새로운
시스템의 라이브러리가 자동으로 채워집니다.

기본적으로 이 도구는 시스템 전체 저장소를 편집하며, 이는 `/System/Settings`
쓰기 정책에 의해 허용된 주체만 변경할 수 있습니다. 일반 계정은 이를
읽을 수만 있으며, `--user`를 통해 자신만의 오버레이로 개인화합니다.
쓰기가 거부되면 그 이유가 표시되고 아무것도 변경되지 않습니다.

성공 시 도구는 표준 출력에 아무것도 출력하지 않습니다. 변경 결과는
표준 정보 스트림(fd 3)에 구조화된 권고 레코드로 출력됩니다. 스크립트는
`3>records.jsonl`을 통해 이를 캡처할 수 있으며, 그 외의 경우에는 무시해도
무방합니다.

## OPTIONS

- `--category <folder>` — `list`와 함께 사용 시 해당 폴더만 표시합니다.
  `add`와 함께 사용 시 항목을 해당 폴더로 분류합니다(매니페스트 선언 재정의).
- `--name <name>` — `add`와 함께 사용 시 매니페스트 이름 대신 표시할
  이름을 지정합니다.
- `--icon <asset>` — `add`와 함께 사용 시 매니페스트 아이콘 대신 지정할
  아이콘 자산(번들의 `Resources/` 내 파일 이름)을 지정합니다.
- `--user` — 시스템 전체 저장소 대신 호출자 고유의 오버레이에 변경 사항을
  적용합니다(또는 `rescan` 시 호출자 자신의 `<home>/Apps`를 검색합니다).
- `-h, -?` — 이 명령의 짧은 도움말을 표시합니다.

## EXAMPLES

- `applib` — 해석된 라이브러리를 폴더별로 표시합니다.
- `applib list --category Games` — 하나의 폴더만 표시합니다.
- `applib add /Apps/chess.app` — 매니페스트의 요청에 따라 번들을 등록합니다.
- `applib add /Apps/tool.app --category Utilities --name "Disk Tool"` —
  목록 게시 선언이 없는 번들을 명시적인 폴더 아래에 등록합니다.
- `applib remove os.tairix.chess` — 식별자로 항목을 삭제합니다.
- `applib hide os.tairix.chess --user` — 자신의 라이브러리에서만 숨깁니다.
- `applib rescan` — 설치 및 나열되어 있지만 아직 시스템 카탈로그에 없는
  모든 번들을 등록합니다.

## EXIT STATUS

- `0` — 목록 표시, 변경, 재검색 또는 짧은 도움말이 완료되었습니다.
- `1` — 저장소, 번들 또는 출력 실패(예: 호출자가 시스템 전체 카탈로그를
  변경할 수 없는 경우). 이유는 진단 스트림에 표시됩니다.
- `2` — 명령줄을 이해할 수 없거나, 폴더 또는 항목을 알 수 없거나, 번들을
  요청대로 등록할 수 없습니다.

## ENVIRONMENT

- `LANG` — 짧은 도움말의 선호 로케일(`fr-FR`과 같은 BCP-47 태그).
- `HOME` — 호출자의 홈 디렉터리. 사용자별 오버레이 및 `--user` 재검색
  루트인 `<home>/Apps`를 지정합니다.
