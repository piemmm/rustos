## NAME

unmount — 마운트된 볼륨 분리

## SYNOPSIS

`unmount [option...] name`

## DESCRIPTION

`name`으로 마운트된 볼륨을 서비스에서 내립니다. 파일시스템과
장치를 플러시하고, `/Storage` 아래의 마운트를 걷어내며, 볼륨의
영속적인 `id::` 루트를 회수합니다. `name`은 볼륨의 카탈로그 이름
(`usb1`) 또는 마운트 지점 경로(`/Storage/usb1`)이며, 시스템 정보
API의 마운트 목록과 대조됩니다.

확정되지 않은 쓰기를 남긴 채 장치가 제거된 볼륨은 마운트 목록에
`unavailable-dirty`(또는 `unavailable-lost`)로 남고, 일반
`unmount`는 거부합니다. 보존된 데이터는 검증된 재삽입을 위해
보관됩니다. `--force`는 의도적인 출구입니다 — 보존 데이터를
버리고 볼륨을 걷어내며, 손실은 감사 로그에 기록됩니다. 정상
볼륨에 대한 `--force`는 여전히 깨끗하게 플러시하고 분리합니다.
깨끗한 확정이 가능하면 아무것도 버려지지 않습니다.

분리에는 마운트 권한(`CAP_FS_MOUNT`)이 필요합니다. 커널이 이를
검사하고 모든 결정을 감사합니다. 영구 부트 볼륨과 시스템 뷰
바인딩은 분리할 수 없습니다.

## OPTIONS

- `-f, --force` — 강제 언마운트: 데이터를 확정할 수 없어도 볼륨을
  걷어내며, 보존 데이터를 버립니다.
- `-?, --help` — 이 명령의 짧은 도움말을 표시합니다.

## EXAMPLES

- `unmount usb1` — `usb1`로 마운트된 볼륨을 깨끗하게 분리.
- `unmount /Storage/usb1` — 마운트 지점으로 지정한 같은 동작.
- `unmount --force usb1` — 사용 불가 볼륨을 보존 데이터를 버리고
  걷어내기.

## EXIT STATUS

- `0` — 볼륨이 분리됨(또는 짧은 도움말이 출력됨).
- `1` — 볼륨을 찾지 못했거나, 분리할 수 없거나, 커널이 분리를
  거부함.
- `2` — 명령줄을 이해하지 못함.

## ENVIRONMENT

- `LANG` — 짧은 도움말에 쓸 선호 로캘(`ko-KR` 같은 BCP-47 태그).
