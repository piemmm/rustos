## NAME

unmount — від'єднати змонтований том

## SYNOPSIS

`unmount [option...] name`

## DESCRIPTION

Виводить із обслуговування том, змонтований під іменем `name`:
файлову систему та пристрій буде скинуто на носій, монтування під
`/Storage` знято, а сталий корінь `id::` тому відкликано. `name` — це
каталожне ім'я тому (`usb1`) або його точка монтування
(`/Storage/usb1`), звірені зі списком монтувань API системної
інформації.

Том, пристрій якого вийняли з непідтвердженими записами, лишається
видимим як `unavailable-dirty` (або `unavailable-lost`), і звичайний
`unmount` відмовляє: утримані дані зберігаються для перевіреного
повторного під'єднання. `--force` — це свідомий вихід: утримані дані
відкидаються, том знімається, а втрату зафіксовано в журналі аудиту.
На справному томі `--force` так само чисто скидає та від'єднує;
нічого не відкидається, коли чисте підтвердження можливе.

Від'єднання вимагає повноваження монтування (`CAP_FS_MOUNT`); ядро
перевіряє його та фіксує кожне рішення. Постійні завантажувальні
томи та системні прив'язки подання не від'єднуються.

## OPTIONS

- `-f, --force` — примусове демонтування: зняти том навіть тоді,
  коли його дані неможливо підтвердити, відкинувши утримані дані.
- `-?, --help` — показати коротку довідку цієї команди.

## EXAMPLES

- `unmount usb1` — чисто від'єднати том, змонтований як `usb1`.
- `unmount /Storage/usb1` — те саме, назване точкою монтування.
- `unmount --force usb1` — зняти недоступний том, відкинувши його
  утримані дані.

## EXIT STATUS

- `0` — том від'єднано (або записано коротку довідку).
- `1` — том не знайдено, він не від'єднується, або ядро відмовило у
  від'єднанні.
- `2` — командний рядок не зрозуміло.

## ENVIRONMENT

- `LANG` — бажана локаль для короткої довідки (позначка BCP-47, як-от
  `uk-UA`).
