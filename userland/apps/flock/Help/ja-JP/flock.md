## NAME

flock — 勧告的なファイルロックを保持したままコマンドを実行する

## SYNOPSIS

`flock [options] ファイル コマンド [引数...]`

## DESCRIPTION

`ファイル`全体を覆う勧告的ロックを取得し、それを保持したまま`コマンド`を
実行して、コマンド自身の終了状態で終了します。したがって同じ`ファイル`を
指定した二つの実行が重なることはなく、スクリプトが自分自身の複製を一つに
保つために必要なのはまさにこれです。

ロックはこの実行が開いたファイルに属するため、実行が終わればシステムが
解放します。正常終了でも、中断でも、異常終了でも同じです。`ファイル`には
何も書き込まれず、あとで片付けるものもないので、次の実行が待たされる古い
ロックは残りません。`ファイル`が無ければ作成されます。

ロックは**勧告的**です。使うことに同意したプログラム同士を調整するもので、
アクセス権を与えも奪いもしません。ロックを取らないプログラムが読み書きを
妨げられることはなく、誰が読み書きできるかは他のファイルと同じく、その
ファイル自身の所有者・許可・アクセス一覧が決めます。

`-n` も `-w` も付けなければ、実行は必要なだけ待ちます。`-n` では直ちに
諦め、`-w` では指定時間の後に諦めます。いずれの場合も諦めれば衝突コード
（`-E` の指定がなければ `1`）で終了し、コマンドは**実行されません**。
よってスクリプトは「ロックが取れなかった」と「コマンドが失敗した」を常に
区別できます。

他のシステムの `flock` にある三つの選択肢は、受け取って無視するのではなく
意図的に用意していません。`-u` と `-o` はシェルがあらかじめ開いた
ファイル記述子に作用しますが、本コマンドにはその形式がありません。`-c` は
引数をシェルに渡すもので、ここでは `flock ファイル elsh -c '...'` と
明示的に書き、どのシェルが動くかを隠しません。いずれかを求めるのは用法
誤りです。要求したロックなしに実行されるのではなく、スクリプトに知らされ
ます。

## OPTIONS

- `-s, --shared` — 共有ロックを取得します。複数の実行が同時に保持でき、いずれも排他ロックの要求を排除します。読み取り側のロックです。
- `-x, --exclusive` — 排他ロックを取得し、他のすべての保持者を排除します。既定値であり、書き込み側のロックです。
- `-n, --nonblock` — 待ちません。ロックが保持されていれば直ちに衝突コードで終了します。
- `-w, --timeout <seconds>` — この秒数（整数）まで待ち、その後衝突コードで終了します。
- `-E, --conflict-code <n>` — `-n` または `-w` が諦めたときの終了状態。既定は `1` です。スクリプトが両者を区別する必要があるなら、コマンド自身が決して返さない値を選んでください。
- `-v, --verbose` — ロックを取得できたかどうかを標準エラーに報告します。
- `-?, --help` — このコマンド自身の短いヘルプを表示します。

## EXAMPLES

- `flock /Users/ian/Library/backup.lock backup-now` — バックアップを
  実行し、別の複製が動いていれば待ちます。
- `flock -n /Storage/db/data.lock compact` — データベースを圧縮し、ロックが
  保持されていれば直ちに `1` で終了します。
- `flock -s -w 30 /Storage/db/data.lock report` — 読み取り側のロックを
  取得し、書き込み側の終了を最大三十秒待ちます。
- `flock -E 99 -n lock task` — ロックが保持されているとき `1` ではなく
  `99` で終了し、`task` の失敗と区別できるようにします。

## EXIT STATUS

- コマンド自身の状態 — ロックを取得し、コマンドが実行された。
- 衝突コード（既定は `1`）— `-n` または `-w` が諦めた。コマンドは実行され
  ていない。
- `1` — 待っても解決しない理由でロックを取得できなかった、またはコマンドを
  実行できなかった。理由は標準エラーに表示されます。
- `2` — コマンド行を解釈できなかった。何もロックせず、何も実行していない。
- `126` — コマンドは見つかったが実行できなかった。
- `127` — コマンドが見つからなかった。

## ENVIRONMENT

- `PATH` — システムおよび利用者のプログラム格納庫の後に、コマンドを探す
  対象となります。
- `HOME` — 利用者自身のプログラム格納庫の位置を決めます。
- `LANG` — 短いヘルプに希望するロケール（`fr-FR` のような BCP-47 タグ）。
