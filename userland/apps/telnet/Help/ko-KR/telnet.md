## NAME

telnet — RFC 854 네트워크 가상 터미널 클라이언트

## SYNOPSIS

`telnet [option...] [host [port]]`

## DESCRIPTION

호스트로 TCP 연결을 열고 터미널을 그쪽으로 중계합니다. 호스트의 출력은 표준
출력에 나타나고, 눌린 키는 호스트로 가며, 이스케이프 문자(기본값 `^]`)는
`telnet>` 명령 해석기로 들어갑니다. 호스트를 주지 않으면 `telnet`은 그 프롬프트
에서 시작하고 `open`으로 연결합니다.

다른 기계의 행 단위 서비스에 닿는 방법이기도 하고, 임의의 TCP 서비스를 손으로
찔러 보는 방법이기도 합니다. `telnet host 80`은 요청을 직접 입력할 수 있는
연결을 엽니다.

호스트는 이름이거나 문자 그대로의 IPv4/IPv6 주소일 수 있습니다. 이름은 시스템의
스텁 리졸버가 해석하며, 그 리졸버는 시스템 정보 API를 통해 설정된 재귀 DNS
서버를 읽습니다. 포트는 숫자입니다. 서비스 데이터베이스가 없으므로 서비스
*이름*은 조용히 포트 23으로 되돌아가는 대신 사용법 오류가 됩니다.

옵션 협상은 RFC 855를 따르며 RFC 1143의 순환 없는 규율을 사용하므로, 같은 말을
반복하는 상대가 클라이언트를 반복하게 만드는 일은 없습니다. 구현된 옵션은
BINARY, ECHO, SUPPRESS GO AHEAD, STATUS, TIMING MARK, TERMINAL TYPE, NAWS,
TERMINAL SPEED, TOGGLE FLOW CONTROL, LINEMODE, NEW-ENVIRON이며, 그 밖의 것은
모두 거절합니다. 구현하지 않은 옵션의 뜻이 바로 그것입니다. RFC 1184의
LINEMODE는 온전히 구현되어 있습니다 — `MODE` 마스크, 지역 문자 표(SLC),
`FORWARDMASK` — 따라서 클라이언트는 서버가 요구하는 대로, 서버가 협상한 문자로
행을 편집합니다.

터미널 창 크기는 연결할 때 NAWS로 보고하고, 바뀔 때마다 다시 보고합니다.
TAIRiX에는 창 변경 신호가 없으므로 입력할 때마다 크기를 다시 읽습니다. 따라서
크기 변경은 다음 키 입력에서 호스트에 도달합니다.

`NEW-ENVIRON`은 `environ` 명령으로 정의하고 내보낸 변수**만** 공개합니다.
클라이언트가 자신의 환경을 보내는 일은 없습니다. `-a`와 `-l`은 로그인 이름을
내보내며, 호출 자체가 스스로 공개하는 것은 그것뿐입니다.

역사적인 도구의 두 명령은 의도적으로 없습니다. `!` 셸 탈출은 없습니다. 적대적인
네트워크 입력을 해석하는 프로그램에 셸을 띄울 권한을 주지 않습니다. `slc check`
도 없습니다. RFC 1184가 `slc export`와 구별되는 선상 형식을 그것에 주지 않기
때문입니다. 소켓 인터페이스는 TCP 긴급 데이터를 노출하지 않으므로 Synch는 Data
Mark 하나로만 전달됩니다. 표준 입력이 파일 끝에 이르면 — `telnet host 80 <
request` 같은 재지정 실행 — 보내는 쪽만 닫고 원격 호스트가 닫을 때까지 세션은 계속
읽습니다. 따라서 응답은 역사적인 도구처럼 버려지지 않습니다.

## OPTIONS

- `-4, --ipv4` — IPv4로만 연결한다.
- `-6, --ipv6` — IPv6로만 연결한다.
- `-8, --binary` — 양방향 8비트 데이터 경로를 요청한다.
- `-L, --eight-bit-output` — 출력 방향에만 8비트 경로를 요청한다.
- `-E, --no-escape` — 이스케이프 문자를 두지 않는다. 모든 입력이 호스트로 간다.
- `-e, --escape <char>` — 이스케이프 문자를 정한다(`^]`, `^A`, 한 글자, 또는
  비워서 없음).
- `-a, --login` — 세션의 로그인 이름을 `NEW-ENVIRON`으로 내보낸다.
- `-l, --user <name>` — `name`을 로그인 이름으로 내보낸다(`-a`를 함축한다).
- `-b, --bind <address>` — 연결하기 전에 이 지역 주소를 묶는다.
- `-d, --debug` — 옵션 협상을 표준 오류에 기록한다.
- `-?, --help` — 이 명령 자신의 짧은 도움말을 보여 준다.

## EXAMPLES

- `telnet example.test` — 지정된 telnet 포트로 세션을 연다.
- `telnet 10.0.2.2 25` — 메일 서비스와 손으로 대화한다.
- `telnet -6 fe80::2` — IPv6로만 연결한다.
- `telnet -l ada host` — 로그인 이름으로 `ada`를 제시한다.
- `telnet -8 host` — 양방향 8비트 경로를 요청한다.
- `telnet` 다음에 `open host` — 명령 프롬프트에서 연결한다.

## EXIT STATUS

- `0` — 세션이 이루어졌다(호스트가 어떻게 끝냈든), 또는 짧은 도움말을 썼다.
- `1` — 세션을 가질 수 없었다. 호스트가 해석되지 않았거나, 소켓이 거절되었거나,
  터미널을 원시 모드로 바꿀 수 없었다.
- `2` — 명령줄을 이해하지 못했다.

## ENVIRONMENT

- `TERM` — TERMINAL TYPE 옵션으로 호스트에 보고된다.
- `USER` — `-a`가 내보내는 로그인 이름.
- `LANG` — 짧은 도움말에 쓸 로케일(`ko-KR` 같은 BCP-47 태그).
