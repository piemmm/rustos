## NAME

telnet — RFC 854 ネットワーク仮想端末クライアント

## SYNOPSIS

`telnet [option...] [host [port]]`

## DESCRIPTION

ホストへ TCP 接続を開き、端末をそこへ中継します。ホストの出力は標準出力に現れ、
キー入力はホストへ送られ、エスケープ文字（既定は `^]`）で `telnet>` コマンド
インタプリタに入ります。ホストを指定しない場合、`telnet` はそのプロンプトから
始まり、`open` で接続します。

別のマシン上の行指向サービスに到達する手段でもあり、任意の TCP サービスを手作業
で問い合わせる手段でもあります。`telnet host 80` は、要求をそのまま打ち込める
接続を開きます。

ホストは名前でも、リテラルの IPv4/IPv6 アドレスでもかまいません。名前はシステム
のスタブリゾルバで解決され、そのリゾルバはシステム情報 API を通じて設定済みの
再帰 DNS サーバーを読み取ります。ポートは数値です。サービスのデータベースは
存在しないため、サービス*名*は黙ってポート 23 に戻るのではなく使用法の誤りと
なります。

オプション交渉は RFC 855 に従い、RFC 1143 のループしない規律を用いるので、
同じことを繰り返す相手がクライアントを繰り返させることはありません。実装して
いるオプションは BINARY、ECHO、SUPPRESS GO AHEAD、STATUS、TIMING MARK、
TERMINAL TYPE、NAWS、TERMINAL SPEED、TOGGLE FLOW CONTROL、LINEMODE、
NEW-ENVIRON です。それ以外はすべて拒否します——未実装のオプションが意味する
のは、まさにそれです。RFC 1184 の LINEMODE は完全に実装しています——`MODE`
マスク、ローカル文字表（SLC）、`FORWARDMASK`——ので、クライアントはサーバー
が求めるとおりに、サーバーが交渉した文字で行編集を行います。

端末のウィンドウサイズは接続時に NAWS で通知し、変化するたびに再度通知します。
TAIRiX にはウィンドウ変更シグナルがないため、入力があるたびにサイズを読み直し
ます。したがってサイズ変更は次のキー入力でホストに届きます。

`NEW-ENVIRON` が開示するのは、`environ` コマンドで定義してエクスポートした
変数**だけ**です。クライアントが自身の環境を送ることはありません。`-a` と
`-l` はログイン名をエクスポートし、それが呼び出し自体が開示する唯一のもの
です。

歴史的なツールの二つのコマンドは意図的にありません。`!` によるシェル脱出は
ありません——敵意ある通信入力を解析するプログラムに、シェルを起動する権限は
与えません。`slc check` もありません。RFC 1184 は `slc export` と区別できる
線上の形式をそれに与えていないからです。ソケットインタフェースは TCP の緊急
データを公開しないため、Synch は Data Mark のみとして送られます。標準入力がファイル終端に達したとき——
`telnet host 80 < request` のようなリダイレクト実行——は送信側だけを閉じ、遠隔ホスト
が閉じるまでセッションは読み取りを続けます。したがって応答は、歴史的なツールのように
捨てられることはありません。

## OPTIONS

- `-4, --ipv4` — IPv4 だけで接続する。
- `-6, --ipv6` — IPv6 だけで接続する。
- `-8, --binary` — 双方向の 8 ビットデータ経路を要求する。
- `-L, --eight-bit-output` — 出力方向のみ 8 ビット経路を要求する。
- `-E, --no-escape` — エスケープ文字なし。すべての入力をホストへ送る。
- `-e, --escape <char>` — エスケープ文字を設定する（`^]`、`^A`、1 文字、または
  空で「なし」）。
- `-a, --login` — セッションのログイン名を `NEW-ENVIRON` でエクスポートする。
- `-l, --user <name>` — `name` をログイン名としてエクスポートする（`-a` を含む）。
- `-b, --bind <address>` — 接続前にこのローカルアドレスを束縛する。
- `-d, --debug` — オプション交渉を標準エラーに記録する。
- `-?, --help` — このコマンド自身の短いヘルプを表示する。

## EXAMPLES

- `telnet example.test` — 割り当てられた telnet ポートでセッションを開く。
- `telnet 10.0.2.2 25` — メールサービスと手作業で対話する。
- `telnet -6 fe80::2` — IPv6 だけで接続する。
- `telnet -l ada host` — ログイン名として `ada` を提示する。
- `telnet -8 host` — 双方向の 8 ビット経路を要求する。
- `telnet` の後に `open host` — コマンドプロンプトから接続する。

## EXIT STATUS

- `0` — セッションが行われた（ホストがどう終えたかに関わらず）、または短い
  ヘルプを書き出した。
- `1` — セッションを持てなかった。ホストが解決できない、ソケットが拒否された、
  または端末を生モードにできなかった。
- `2` — コマンド行を理解できなかった。

## ENVIRONMENT

- `TERM` — TERMINAL TYPE オプションでホストに通知される。
- `USER` — `-a` がエクスポートするログイン名。
- `LANG` — 短いヘルプに用いるロケール（`ja-JP` のような BCP-47 タグ）。
