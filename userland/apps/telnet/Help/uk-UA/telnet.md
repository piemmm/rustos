## NAME

telnet — клієнт мережевого віртуального термінала (RFC 854)

## SYNOPSIS

`telnet [option...] [host [port]]`

## DESCRIPTION

Відкриває TCP-з'єднання з вузлом і передає йому термінал: вивід вузла
з'являється на стандартному виводі, натискання клавіш ідуть до вузла, а
символ виходу (`^]` типово) відкриває інтерпретатор команд `telnet>`. Без
вузла `telnet` починає з цього запиту, а `open` встановлює з'єднання.

Це і спосіб дістатися до рядково-орієнтованої служби на іншій машині, і
спосіб вручну звернутися до будь-якої служби TCP — `telnet host 80` відкриває
з'єднання, у яке можна ввести запит.

Вузол може бути іменем або літеральною адресою IPv4/IPv6. Ім'я розв'язується
простим системним розв'язувачем, який читає налаштовані рекурсивні
DNS-сервери через API системної інформації. Порт — це число: бази даних служб
немає, тож *ім'я* служби є помилкою використання, а не тихим поверненням до
порту 23.

Узгодження параметрів відповідає RFC 855 із дисциплиною без циклів із
RFC 1143, тож партнер, який повторюється, ніколи не змушує клієнта
повторюватися. Реалізовані параметри: BINARY, ECHO, SUPPRESS GO AHEAD,
STATUS, TIMING MARK, TERMINAL TYPE, NAWS, TERMINAL SPEED, TOGGLE FLOW
CONTROL, LINEMODE і NEW-ENVIRON; усе інше відхиляється — саме це й означає
нереалізований параметр. LINEMODE (RFC 1184) реалізовано повністю — маска
`MODE`, таблиця локальних символів (SLC) і `FORWARDMASK` — тож клієнт
редагує рядок так, як просить сервер, тими символами, які сервер узгодив.

Розмір вікна повідомляється через NAWS під час з'єднання і за кожної зміни.
TAIRiX не має сигналу про зміну розміру, тож розмір перечитується щоразу, коли
ви друкуєте; зміна розміру досягає вузла з наступним натисканням клавіші.

`NEW-ENVIRON` розкриває **лише** ті змінні, які ви визначили та експортували
командою `environ`; клієнт ніколи не надсилає власне середовище. `-a` і `-l`
експортують ім'я входу — це єдине, що виклик розкриває самотужки.

Двох команд історичного інструмента свідомо немає. Немає виходу до оболонки
`!`: програмі, що розбирає ворожі мережеві дані, не надають права запускати
оболонку. Немає `slc check`, бо RFC 1184 не дає йому форми на дроті, відмінної
від `slc export`. Термінові дані TCP не доступні через інтерфейс сокетів, тож
Synch подорожує самою лише позначкою Data Mark. Коли стандартний ввід досягає
кінця файлу — перенаправлений виклик на кшталт `telnet host 80 < request` —
закривається лише бік передавання, і сеанс читає далі, доки віддалений вузол
також не закриє з'єднання, тож відповідь не відкидається, як це робить
історичний інструмент.

## OPTIONS

- `-4, --ipv4` — з'єднуватися лише через IPv4.
- `-6, --ipv6` — з'єднуватися лише через IPv6.
- `-8, --binary` — просити 8-бітний шлях даних в обидва боки.
- `-L, --eight-bit-output` — просити 8-бітний шлях лише на виході.
- `-E, --no-escape` — без символу виходу; усе йде до вузла.
- `-e, --escape <char>` — задати символ виходу (`^]`, `^A`, один символ або
  порожнє значення, щоб не мати жодного).
- `-a, --login` — експортувати ім'я входу сеансу через `NEW-ENVIRON`.
- `-l, --user <name>` — експортувати `name` як ім'я входу (передбачає `-a`).
- `-b, --bind <address>` — привʼязати цю локальну адресу перед з'єднанням.
- `-d, --debug` — трасувати узгодження параметрів на стандартний вивід помилок.
- `-?, --help` — показати коротку довідку цієї команди.

## EXAMPLES

- `telnet example.test` — відкрити сеанс на призначеному порту telnet.
- `telnet 10.0.2.2 25` — вручну поговорити з поштовою службою.
- `telnet -6 fe80::2` — з'єднатися лише через IPv6.
- `telnet -l ada host` — запропонувати `ada` як ім'я входу.
- `telnet -8 host` — просити 8-бітний шлях в обидва боки.
- `telnet`, потім `open host` — з'єднатися з командного запиту.

## EXIT STATUS

- `0` — сеанс відбувся (як би вузол його не завершив), або було виведено
  коротку довідку.
- `1` — сеанс був неможливий: вузол не розв'язався, сокет відхилено або
  термінал не вдалося перевести в сирий режим.
- `2` — командний рядок не зрозуміли.

## ENVIRONMENT

- `TERM` — повідомляється вузлу через параметр TERMINAL TYPE.
- `USER` — ім'я входу, яке експортує `-a`.
- `LANG` — бажана локаль для короткої довідки (мітка BCP-47, як-от `uk-UA`).
