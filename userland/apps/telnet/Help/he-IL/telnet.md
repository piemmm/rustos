## NAME

telnet — לקוח המסוף הווירטואלי הרשתי (RFC 854)

## SYNOPSIS

`telnet [option...] [host [port]]`

## DESCRIPTION

פותח חיבור TCP למאחסן ומעביר אליו את המסוף: הפלט של המאחסן מופיע בפלט התקני,
הקשות המקלדת נשלחות אליו, ותו הבריחה (`^]` כברירת מחדל) נכנס למפרש הפקודות
`telnet>`. בלי מאחסן, `telnet` מתחיל באותה שורת בקשה, ו-`open` מתחבר.

זו הדרך להגיע לשירות מונחה־שורות במכונה אחרת, וגם הדרך לתחקר כל שירות TCP
בעבודת יד — `telnet host 80` פותח חיבור שאפשר להקליד אליו בקשה.

המאחסן יכול להיות שם או כתובת IPv4/IPv6 מילולית. שם מתורגם בידי פותר הביניים
של המערכת, הקורא את שרתי ה-DNS הרקורסיביים המוגדרים דרך ממשק מידע המערכת.
הפורט הוא מספר: אין מסד נתוני שירותים, ולכן *שם* שירות הוא שגיאת שימוש ולא
נסיגה שקטה לפורט 23.

המשא ומתן על האפשרויות מקיים את RFC 855 עם המשמעת נטולת המעגלים של RFC 1143,
ולכן עמית שחוזר על עצמו אינו גורם ללקוח לחזור על עצמו. האפשרויות הממומשות הן
BINARY, ECHO, SUPPRESS GO AHEAD, STATUS, TIMING MARK, TERMINAL TYPE, NAWS,
TERMINAL SPEED, TOGGLE FLOW CONTROL, LINEMODE ו-NEW-ENVIRON; כל השאר נדחות,
וזו בדיוק משמעותה של אפשרות שאינה ממומשת. LINEMODE (RFC 1184) ממומש במלואו —
מסכת ה-`MODE`, טבלת התווים המקומיים (SLC) ו-`FORWARDMASK` — ולכן הלקוח עורך את
השורה כפי שהשרת מבקש, עם התווים שהשרת סיכם.

גודל חלון המסוף מדווח דרך NAWS עם ההתחברות ושוב בכל שינוי. ל-TAIRiX אין אות
שינוי חלון, ולכן הגודל נקרא מחדש בכל הקשה; שינוי גודל מגיע אל המאחסן בהקשה
הבאה שלך.

‏`NEW-ENVIRON` חושף **רק** משתנים שהגדרת וייצאת בפקודת `environ`; הלקוח לעולם
אינו שולח את הסביבה שלו. `-a` ו-`-l` מייצאים שם התחברות, וזה הדבר היחיד
שהפעלה חושפת מעצמה.

שתי פקודות של הכלי ההיסטורי נעדרות בכוונה. אין בריחה למעטפת `!`: תוכנית
שמפרקת קלט רשת עוין אינה מקבלת את הסמכות להריץ מעטפת. אין `slc check`, מפני
ש-RFC 1184 אינו נותן לה צורה על הקו הנבדלת מ-`slc export`. ממשק השקעים אינו
חושף נתוני TCP דחופים, ולכן Synch נוסע כסימן Data Mark לבדו. כאשר הקלט התקני מגיע לסוף הקובץ — הפעלה
מנותבת כגון `telnet host 80 < request` — נסגר רק צד השליחה, והשיחה ממשיכה
לקרוא עד שגם המאחסן המרוחק סוגר, ולכן התשובה אינה נזרקת כפי שהכלי ההיסטורי
זורק אותה.

## OPTIONS

- `-4, --ipv4` — להתחבר דרך IPv4 בלבד.
- `-6, --ipv6` — להתחבר דרך IPv6 בלבד.
- `-8, --binary` — לבקש נתיב נתונים של 8 סיביות בשני הכיוונים.
- `-L, --eight-bit-output` — לבקש נתיב 8 סיביות בפלט בלבד.
- `-E, --no-escape` — בלי תו בריחה; כל הקשה נשלחת אל המאחסן.
- `-e, --escape <char>` — לקבוע את תו הבריחה (`^]`, `^A`, תו אחד, או ריק כדי
  שלא יהיה כלל).
- `-a, --login` — לייצא את שם ההתחברות של השיחה דרך `NEW-ENVIRON`.
- `-l, --user <name>` — לייצא את `name` כשם התחברות (גורר `-a`).
- `-b, --bind <address>` — לכרוך את הכתובת המקומית הזאת לפני ההתחברות.
- `-d, --debug` — לתעד את המשא ומתן על האפשרויות בפלט השגיאה התקני.
- `-?, --help` — להציג את העזרה הקצרה של הפקודה הזאת.

## EXAMPLES

- `telnet example.test` — לפתוח שיחה בפורט telnet המוקצה.
- `telnet 10.0.2.2 25` — לדבר בעבודת יד עם שירות דואר.
- `telnet -6 fe80::2` — להתחבר דרך IPv6 בלבד.
- `telnet -l ada host` — להציע את `ada` כשם התחברות.
- `telnet -8 host` — לבקש נתיב 8 סיביות בשני הכיוונים.
- `telnet` ואחר כך `open host` — להתחבר משורת הבקשה של הפקודות.

## EXIT STATUS

- `0` — השיחה התקיימה (כיצד שהמאחסן סיים אותה), או שנכתבה העזרה הקצרה.
- `1` — לא ניתן היה לקיים שיחה: המאחסן לא תורגם, השקע נדחה, או שלא היה אפשר
  להעביר את המסוף למצב גלמי.
- `2` — שורת הפקודה לא הובנה.

## ENVIRONMENT

- `TERM` — מדווח למאחסן דרך אפשרות TERMINAL TYPE.
- `USER` — שם ההתחברות ש-`-a` מייצא.
- `LANG` — המקומיות המועדפת לעזרה הקצרה (תג BCP-47 כגון `he-IL`).
