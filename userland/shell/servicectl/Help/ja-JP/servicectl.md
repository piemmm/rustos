## NAME

servicectl — システムサービスを開始・停止・有効化・無効化する

## SYNOPSIS

`servicectl [-h | -?] start|stop|enable|disable SERVICE`

## DESCRIPTION

サービスマネージャの、ケーパビリティで保護された制御エンドポイントを通じ
て、登録済みサービスの実行状態の変更を依頼します。決定するのはマネージャ
であり、本ツールは要求を符号化して応答を報告するだけです。

エンドポイントに到達できること自体が権限です。アカウントの上限に
`CAP_SERVICE_CONTROL` がなければ、カーネルはマネージャが見る前に呼び出し
を拒否するため、非特権アカウントは尋ねることさえできません。

- `start SERVICE` — 登録済みで現在停止しているサービスを今すぐ起動しま
  す。そのサービスが要求する準備条件は依然として適用されます。条件が満た
  されないサービスは、それを支えられないシステムに起動されるのではなく拒否
  されます。
- `stop SERVICE` — 実行中のサービスを、その依存側とともに依存関係の逆順で
  穏当に停止します。まず終了を依頼し、猶予期間の経過後にのみ強制終了しま
  す。
- `enable SERVICE` — サービスを登録済みとして記録し、以後の起動ごとに
  マネージャが立ち上げるようにして、いま起動する。
- `disable SERVICE` — 未登録として記録し、以後どの起動でも立ち上がらない
  ようにして、いま停止する。

成功時には、マネージャがサービスをどの状態に残したかを一行で示します。

どちらの変更も、自分のセッションだけでなくマシン上のすべての主体に影響しま
す。`start` と `stop` が変えるのは*実行中*のシステムだけなので、登録済みの
サービスは次回起動時に戻ります。`enable` と `disable` は登録そのものを変える
ので、起動をまたいで残ります。

## OPTIONS

- `-h, -?` — このコマンド自身の短いヘルプを表示して終了する。
- `--` — オプションの終わり。名前がハイフンで始まるサービスも指名できる。

## EXIT STATUS

- `0` — 操作が適用された、または短いヘルプが表示された。
- `1` — マネージャが操作を拒否した、または制御エンドポイントに到達できな
  かった。
- `2` — コマンドラインを解釈できなかった。何も送信していない。

## ENVIRONMENT

- `LANG` — 短いヘルプに使うロケール（`fr-FR` のような BCP-47 タグ）。
