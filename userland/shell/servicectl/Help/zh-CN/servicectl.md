## NAME

servicectl — 启动、停止、启用和停用系统服务

## SYNOPSIS

`servicectl [-h | -?] start|stop|enable|disable SERVICE`

## DESCRIPTION

通过服务管理器受能力保护的控制端点，请求它更改某个已注册服务的运行状态。
决定权在管理器：本工具只负责编码请求并报告答复。

能够到达该端点本身就是授权。若您账户的上限中没有
`CAP_SERVICE_CONTROL`，内核会在管理器看到之前拒绝该调用，因此无特权账户
连询问都无法做到。

- `start SERVICE` — 立即启动一个已注册但当前已停止的服务。它所要求的就绪
  条件仍然适用：条件未满足的服务会被拒绝，而不是被启动到一个无法支撑它的
  系统里。
- `stop SERVICE` — 优雅地停止一个正在运行的服务，并按依赖的反序停止其依赖
  方。先请求服务自行退出，只有在其宽限期过后才强制结束。
- `enable SERVICE` — 将服务记录为已登记，使管理器在每次启动时都将其拉起，
  并立即启动它。
- `disable SERVICE` — 将其记录为未登记，使此后任何启动都不再拉起它，
  并立即停止它。

成功时会有一行指明管理器将该服务留在了哪个状态。

两类改变都会影响机器上的每一个主体，而不只是您自己的会话。`start` 与 `stop`
只改变*正在运行*的系统，因此已登记的服务会在下次启动时回来；`enable` 与
`disable` 改变的是登记本身，因此可以跨越启动。

## OPTIONS

- `-h, -?` — 显示本命令自己的简短帮助并退出。
- `--` — 结束选项，使名称以短横线开头的服务仍可被指名。

## EXIT STATUS

- `0` — 操作已应用，或已显示简短帮助。
- `1` — 管理器拒绝了该操作，或无法到达控制端点。
- `2` — 未能理解命令行；未发送任何内容。

## ENVIRONMENT

- `LANG` — 简短帮助所偏好的区域设置（BCP-47 标签，例如 `fr-FR`）。
